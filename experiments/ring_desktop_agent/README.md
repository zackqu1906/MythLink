# 戒指 → 桌面 Agent 独立测试

Mythlink 项目内的实验模块，复用 `src/proximic_ring` 的戒指连接、手势与火山引擎 ASR。
使用本机 Codex App Server 运行任务，通过 Computer Use 按任务选择桌面应用。
客户端不再限制应用白名单、操作目录、保存目录或只能处理测试文档。
尚未接入 Mythlink 主界面或安装包；新应用和复杂场景仍需实机验证。

## 启动

在项目根目录执行：

```bash
./scripts/start-ring-agent.sh
```

一条命令启动原生请求窗口、Agent 和戒指连接。需要已登录且可用 Computer Use 的 Codex、
Xcode Command Line Tools，以及已经在 Mythlink 配好的戒指和火山引擎 ASR。
脚本优先使用项目的 `.runtime/venv/bin/python`，可用 `RING_AGENT_PYTHON` 指定环境。
请先在 Mythlink 主应用断开戒指，避免两个控制程序同时连接。此脚本不自动关闭 Mythlink。

不再指定固定的默认输出目录。按用户要求选择位置，未指定时沿用应用当前 / 默认保存位置，
必要时询问。可以启动时提供一个可选的保存偏好：

```bash
./scripts/start-ring-agent.sh --output-dir "$HOME/Desktop/Mythlink-Agent-Test"
```

`--output-dir` 只是未指定位置时的偏好，不构成操作或保存边界，启动时不会自动创建该目录。
可按任务要求处理已有或新建文档，保存格式由任务和应用决定。
旧原型的临时目录限制、项目默认输出目录及固定 RTF 格式要求均已移除。
日志目录 `--runtime-dir` 仅用于控制程序自己的状态与诊断，不限制 Agent 操作文件的位置。
macOS 与服务端的实际权限仍然生效，客户端不会绕过系统权限。

其他命令：

```bash
./scripts/start-ring-agent.sh --check      # 只检查环境，不启动任务或蓝牙
./scripts/start-ring-agent.sh --no-ring    # 通过窗口文字输入测试
./scripts/start-ring-agent.sh --duration 1800
./scripts/start-ring-agent.sh --help
```

点击“结束测试”、关闭窗口或在终端按 Ctrl+C，都会关闭本次 Agent 和戒指连接。
同一项目的启动器有单实例锁；它不能阻止 Mythlink 主应用或旧版临时脚本另行连接戒指。

## 手势

| 状态 | 手势 | 行为 |
| --- | --- | --- |
| 未录音 | 双击 | 开始语音，可在 Agent 执行期间使用 |
| 正在录音 | tap | 结束录音；空闲时开始任务，执行中加入 FIFO 等待队列 |
| 正在录音 | 右滑 | 结束录音，将识别文字作为 steer 发给录音开始时的任务 |
| 正在回答 Agent 的追问 | tap 结束录音 | 回答对应问题 |
| 有请求选项且未录音 | 上滑 / 下滑 | 选择上一项 / 下一项 |
| 有请求选项且未录音 | tap | 确认当前选项 |
| 未录音 | 右滑 | 无任务控制动作 |
| 任意状态 | 左滑 | 取消当前任务、当前录音及等待队列 |

ASR 延迟结果绑定原任务 / 原问题；任务已经结束时，steer 不会误发给下一条任务。
取消不会撤销已经发生的输入或保存。

## 窗口分区

- 顶部：运行状态、取消、结束测试。
- 授权与权限提示：应用 / 命令 / 文件 / 网络授权、自动允许开关、处理数量和记录。
- 中间任务进展：Agent 输出、最近任务识别和保存位置。
- Agent 提问：单独的蓝色问题卡片、服务端选项、回答文本框和“提交回答”。
- 固定底部：新任务输入和 steer。这里提交的内容即使有追问也只会排队，不会代替回答。

有追问时双击 tap 开始录音，单击 tap 结束后回答录音开始时的那个问题。
识别过程显示在回答卡片里，答案不会写入新任务输入区；问题失效后不会误答下一个问题。
追问中的“取消”等文本按答案提交，全局取消仍使用左滑或取消按钮。

## 自动允许授权

勾选“自动允许授权请求（本次运行）”，立即处理已等待和随后到达的可处理授权。
支持空表单 MCP 确认、命令执行、文件修改和结构已接入的文件 / 网络权限申请。
每次自动批准都会留下记录，界面显示累计数量；未开启时按正常请求选项确认。

Agent 的 `ask_ring_user` 和 `requestUserInput` 追问不会自动回答、选项或跳过。
Safari 等 Computer Use 应用授权即使带有 `riskLevel: high`，也会按应用授权自动处理；
这是整个应用访问的风险标记，不应导致读取、点击或输入每一步都重新弹窗。
已选择“允许此对话 / 始终允许”的应用同样复用授权；仍逐次回复服务端以便取消或修改时拒绝后续动作。
必须填写的表单、登录 / 系统弹窗、未知请求，以及独立的非 `low` 风险操作确认，
仍等待用户处理，不伪造输入或绕过操作系统权限。

开关默认关闭，仅在本次运行生效；关闭后停止新的自动批准，重启后也恢复关闭。
客户端逐次允许以保留取消边界，不自动写入永久应用授权或命令 / 网络规则。
如果接口只提供会话授权，则使用该接口提供的范围；关闭开关不撤销已经生效的权限。
取消后拒绝后续动作，steer 后旧动作失效。

## 请求与授权

收到的请求在浮动窗口展示来源、内容、选项数和手势映射，新请求会将窗口置前。
保留服务端支持的选项，不追加“语音回答 / 取消任务”等选项；语音、取消是独立控件。
普通应用内操作可复用已确认的应用授权。自动允许未开启时，新应用及额外权限需要确认。
未知请求不会自动通过。
本实验目前不支持的请求会展示原因；macOS 原生系统权限仍可能需要用户在系统窗口处理。
不能把此窗口视为对所有系统级权限弹窗的完整代理。

Computer Use 请求支持时显示“允许此对话 / 始终允许 / 拒绝”。为取消和修改保留后续动作拦截，
本实验由戒指客户端缓存应用授权，向服务端逐次回复已有授权。
“始终允许”保存在当前运行目录的 `app-grants.json`，只覆盖用户已授权应用内的普通操作，
不等于修改了全局 Codex 的权限配置。
应用 ID 不在显示名称映射里时仍可授权，界面直接显示该 ID。额外或风险较高的应用操作
仍显示服务端请求，确认后执行；未实现的表单 / 身份验证协议显示原因。
客户端已能展示和回复命令、文件修改以及额外文件 / 网络权限的标准审批请求。
桌面交互仍使用 Computer Use；自动允许不会修改服务端审批策略或沙箱配置。

已移除暂停 / 继续与逐调用单动作限制；已经发出的动作可能先完成。
steer 使用 `turn/steer`；取消使用 `turn/interrupt`，并先处理正在等待的授权请求。

## 文件与日志

主界面现已集成右下角 Agent 工作区，入口和手势见[项目说明](../../README.md#主界面-agent-工作区macos)。
下面四个 Python 模块现在是兼容入口，共用实现位于 `src/proximic_ring/agent_workflow/agent/`；
独立测试的原生窗口与启动器继续保留。主界面不使用本测试器的第二条 BLE 连接。

- `flow.py`：Agent 生命周期、任务队列、取消 / steer。
- `interaction.py`：录音状态和手势路由。
- `requests_ui.py`：服务端请求转换为请求卡片。
- `rpc.py`：App Server JSON-RPC stdio 客户端。
- `Console.swift`：原生浮动请求窗口。
- `launcher.py`：环境检查、编译、单实例锁和进程清理。

状态、编译产物、授权缓存、事件及音频日志位于 `.cache/ring-agent-demo/`，
可用 `--runtime-dir` 改变位置；默认缓存目录已被项目忽略。任务结果保存在用户选择的位置。
ASR 配置从当前用户的 Mythlink Preferences 读取，不复制或输出 API key。
本地日志包含语音识别文本与任务内容；`audio/` 会保存戒指音频诊断。
