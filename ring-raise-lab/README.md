# 戒指抬到嘴边实验

目标：采集戒指原始六轴和麦克风，为「抬到嘴边并对戒指说话」的时序融合模型准备数据。当前已实现双路采集、试听和三种独立标签；已有训练 / 评估仍是 IMU 基线，不是融合模型。不会启动语音助手、注入键鼠或修改 Mythlink。

**双路采集说明、苹果论文链接、对齐限制与后续模型设计见 [docs/multimodal.md](docs/multimodal.md)。**

当前交付的是可运行流程。没有已采集的本任务真实标注数据，也没有经过实物验收的抬手模型。`demo` 和自动测试产生的模型只验证代码流程，不能作为识别效果证据。

## 1. 启动

在这台电脑上双击本目录的 **打开抬手实验台.command**，或：

```sh
cd /Users/admin/Downloads/ProximicVoice-main/ring-raise-lab
./run.sh serve
```

打开 `http://127.0.0.1:8767`。先扫描并选择设备，点击「连接戒指」。连接待机不录音；点击「开始采集」才启动数据流。「停止并保存」保留连接，「断开连接」停止两路并释放 BLE，采集中断链保留部分文件并标记不完整。先在 Mythlink、手机及其他实验程序中释放同一枚戒指的连接。若系统请求蓝牙权限，需要给运行 Python 的终端 / 应用授权。

启动脚本优先使用本目录 `.venv`；本机尚无独立虚拟环境时使用已有 `.build/packaging-venv`，不修改它的依赖。搬到其他机器时：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./run.sh serve
```

推荐 Python 3.11 或 3.12。界面默认只监听本机。关闭终端的 Ctrl-C 会停止采集并尝试保存。

## 2. 先验证六轴，再采动作

供应包：`ring-studio-ringo-lab-firmware-20261014.zip`。其中两个协议文件与 ADPCM 解码器逐字保存在 `vendor/ring_studio/`，原始成员路径与 SHA-256 见 `vendor/PROVENANCE.json`。本工具没有执行包内 README 的烧录步骤，也不包含烧录入口。SDK 支持原始数据不等于当前戒指已经运行包内的 `2.0.2.public_dev` 固件；每段采集实际读取并保存版本。

| 项目 | 本实验约定 |
| --- | --- |
| 发送命令 | `21 00 c8 00 c8 00 d0 07 10 0a 00 00` |
| 请求配置 | 200 Hz，±16 g，±2000 °/s，10 帧/包，raw，LN 六轴 |
| 接受通知 | `21 02`，每帧 6 个小端有符号 int16 |
| 加速度 | `raw × 9.80665 / 2048`，m/s²，**保留重力** |
| 角速度 | `raw × π / (180 × 16.4)`，rad/s；不是角度 |
| 坐标系 | 设备线上原始轴，不推断 X/Y/Z 对应哪根手指方向 |
| 时间 | 设备包末 uint32 毫秒时间戳；包内时间由原 SDK 按 200 Hz 回填 |

先选「信号检查」，分别检查单独 IMU、单独麦克风，再检查双路。IMU 可录 120 秒，执行：

1. 戒指放稳约 10 秒：加速度模长应接近 9.81 m/s²，陀螺仪接近零。
2. 分别换六个静止朝向，每个停 5–10 秒；检查重力在三轴上的分量与正负变化。轴名仍按设备定义，不直接改成“朝嘴方向”。
3. 分别绕不同轴转动，确认相应角速度变化；记录佩戴手、手指、朝向和松紧。
4. 查看录制的数据检查结果。若包末估计采样率偏离 200 Hz、物理量数量级错误、断流或饱和，先排查，不开始模型训练。

`190–210 Hz` 是首版工程容差，不是厂商精度保证。包内 5 ms 的整齐间隔不能证明实际 ODR。缺口所跨窗口会丢弃，不跨缺口插值。当前首版不混合固件版本。

## 3. 小批次试采与人工复核

v2 采集把运动、语音与意图分开：相同抬手即使不说话或对别人说话，也保留抬手运动阶段，最终交互意图另标。先采 10–20 次检查质量，覆盖不同起点（桌面、腿上、自然垂手）、自然快慢、坐姿 / 站姿。不要只采一种夸张动作。首版先固定同一人、同一手指和佩戴方向。

标签含义：

| 标签 | 定义 |
| --- | --- |
| `background` | 不处于指定口旁抬手运动，包括喝水、摸脸等其他运动 |
| `raising` | 从开始执行口旁抬手，到实际到达嘴边之前（不由说话意图决定） |
| `near_mouth` | 到达本人预先约定的说话姿势，至开始放下之前 |
| `lowering` | 从开始放下，到返回背景姿态 |
| `unknown` | 无法确认、未完成、发生遮挡或边界不清；不作为监督标签 |

“嘴边”是可观察的姿势标签，单枚 IMU 没有测量嘴部距离。开始试采前，用同一个人的自然说话姿势固定定义，并在备注 / 视频中记录。

界面会按不同停顿长度给出引导，生成 **未复核的草稿**。实际动作可能早于或晚于提示，不能直接拿草稿训练。推荐用独立手机视频拍到手和嘴、同时拍到屏幕计时，在录制开始与结束各做一次清楚可见的同步动作。利用屏幕时间、IMU 动作峰和视频三者核对起止点；BLE 接收时间与录像不是硬件同步，记录无法消除的时间误差。界面不自动录像。

到「复核标注」中检查曲线、修正起止时间，填写复核者与依据。不要靠回忆强行填标签；不确定则标 unknown 并重采。每个目标 `trial_id` 必须包含连续的 raising → near_mouth → lowering；未完成的尾段不能当成完整事件。`annotations.json` 与原始 IMU 哈希绑定，旧版本保留在 `annotation_history/`。

每批还要采抬手不说话、抬手侧谈、说话不抬手、旁人语音，分别标运动、声音与意图。独立日常负例录制至少覆盖：打字/鼠标、喝水、吃东西、摸脸、托腮、调整眼镜/头发、看手机/接电话、捂嘴咳嗽/打哈欠、走动取物。**喝水和摸嘴即使接近嘴边也标 background**，并保留活动类别。负例不要只采静止。

## 4. 正式个人试验：先冻结划分

至少 3 个独立批次；建议不同时间、重新佩戴，每批都采正例和连续负例。先做个人模型，不把同一人的结果宣称为新用户泛化。

建议起步规模（实验设计建议，不是论文结论或性能保证）：每批 30–50 次目标动作、10–20 分钟多样负例。真实低误触验证需要更长的连续日常数据。

同次佩戴中的所有录制使用相同 `participant/visit`，它是划分单位；同一批次不得一部分训练、一部分测试。填写 `splits.json`，目录名可从界面复制：

```json
{
  "mode": "personal",
  "train": ["20261102_目标录制", "20261102_负例录制"],
  "val": ["另一批次_目标", "另一批次_负例"],
  "test": ["第三批次_目标", "第三批次_负例"]
}
```

示例名称是占位符。若做多人泛化，用 `cross_subject`，程序会禁止任何同一参与者跨集合。禁止随机拆分相邻滑窗。

```sh
./run.sh audit data/sessions/实际录制目录
./run.sh prepare --plan splits.json --out datasets/pilot-v1
```

未复核、文件被改动、单位不匹配、错误模式、采样率异常、批次泄漏、缺少四类或没有独立负例，都会拒绝构建。原始采集保持不变；数据集保存来源哈希与全部划分。不要手工移动窗口来改善验证分数。

## 5. IMU 基线、CNN 与一次测试

以下命令不读取音频。不能将其结果称为融合识别或语音意图准确率；新旧运动标签定义也不能混用。

```sh
./run.sh train --dataset datasets/pilot-v1 --out runs/stats-v1 --model stats --epochs 40
./run.sh train --dataset datasets/pilot-v1 --out runs/cnn-v1 --model cnn --epochs 40
```

先比较两者 `validation.html`：统计特征线性模型是基线，小型因果 1D CNN 是时序模型。二者使用相同六轴、窗口和评估。模型不直接套用 WritingRing 的去重力步骤；当前任务需要检验姿态信息的价值。只用训练集拟合均值和标准差；只用验证集选 checkpoint / 阈值。

默认过去 1 秒窗口、200 Hz 输入，即每窗 6×200 个值，每 100 ms 更新一次，不读取预测时刻之后的数据。语音分支同样使用过去 1 秒，沿用 decoupled 原始 CNN 和前端。1 秒是历史长度，不代表每次触发都固定等待 1 秒；实际触发延迟需要结合数据到达、模型预测和事件规则实测。训练排除标注边界前后 150 ms；验证 / 测试不删除难辨的边界帧。窗口大小与边界容差是首版假设，若要调整只看验证集，并保留实验版本。旧数据集和模型保留各自记录的窗口配置；改用 1 秒须重新 prepare 并训练，原始连续录制可复用。

默认事件规则：near_mouth 分数连续 3 个更新点超过阈值才产生候选；背景分数连续 5 点 ≥0.6，且距上次候选至少 1 秒才重新允许触发。数据缺口清空规则状态。所有延迟与漏检都包括这套规则的影响。

验证集阈值按默认每小时误触 ≤1 的预算选择；这是经验约束，不是已证明的误触率。若无法获得有效候选，可能选择 >1 的禁用阈值，报告会明确提示验证未通过。

确定模型之后，再运行一次留出测试：

```sh
./run.sh evaluate --run runs/cnn-v1
```

产生 `test.html`、`test.json`、`test_predictions.npz`。关注事件召回、漏检、每小时误触、重复触发、到嘴边时刻的延迟 P50/P90、排除事件及失败活动。CPU 推理耗时不包含 BLE、窗口历史和显示延迟。

零误触不能写成“误触率为零”：观察 T 小时零误触，Poisson 单侧 95% 上限约为 3/T 次/小时；事件相关性还会削弱该假设。短试采的结果只能作可行性检查。用测试错误调参后，原测试集就成为开发资料，需要再采新的留出测试。

## 6. 回放与实时观测

```sh
./run.sh replay --run runs/cnn-v1 --session data/sessions/实际录制目录 --out runs/cnn-v1/replay.csv
./run.sh live --run runs/cnn-v1 --device '准确设备地址或完整名称' \
  --participant p01 --visit live01 --hand right --finger index \
  --mount-note '与训练时一致的佩戴朝向' --seconds 120
```

实时模式保存新的 raw 包、六轴和候选分数，只打印动作候选。禁止把合成自检模型用于真实设备；固件版本也必须匹配。实时观测不自动产生训练真值。
