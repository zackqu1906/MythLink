# Ringo IMU Speech Lab

独立本地实验程序，采集原始六轴 IMU 与戒指麦克风，观察讲话时是否有可重复变化。录制结束后可同步查看整段、放大任意区间、读取六轴和音量数值、播放选中片段。仅使用戒指麦克风，不访问电脑麦克风。

## 启动与实验

双击 `scripts/imu-speech-lab.command`，或在仓库根目录执行：

```sh
./scripts/imu-speech-lab.command
```

浏览器打开 `http://127.0.0.1:8766`。启动器优先使用 `.build/packaging-venv`，其次 `.venv`；依赖 Python 3.11+、numpy、bleak。macOS 需要运行程序的宿主有蓝牙权限，不需要电脑麦克风权限。

自动语音分段使用本地 `webrtcvad-wheels`，安装完整实验依赖：`python -m pip install -r tools/imu_speech_lab/requirements.txt`。缺少该依赖会在回看界面明确提示，不会把音量门限伪装成语音检测，也不影响原始采集。

1. 在 iPhone 的 nRF Connect / Device Manager、Mythlink 等其他程序中断开戒指。
2. 默认连接 `Ringo8F56`，使用新 SDK 的 raw 六轴和戒指麦克风。佩戴戒指，把手放稳，记录姿势、距离和松紧。
3. 点击“连接并开始采集”。确认六轴、戒指音量均有数据，再点击“开始 65 秒引导实验”。每阶段准备 3 秒，采集 10 秒：静默 → 说话 → 静默 → 长音“啊” → 静默。引导结束自动保存。
4. 手动对照可选择“旁人说话”“音箱播放”“只动手”“同时说话”。每段至少 10 秒，重复不同条件。按钮或数字键 0–7 标记条件；程序不会自动验证标签是否真实。
5. 手动录制用“停止并保存报告”结束。网页会自动加载完整回看数据。关闭网页不会停止录制，退出前先停止；终端 Ctrl+C 也会保存并断开。

“用合成数据检查界面”不连接硬件，其数据故意包含相关信号，目录、元数据和页面均标记 DEMO，不能作为物理实验结果。

## 新 SDK 与数据单位

使用用户提供的 `ring-studio-ringo-lab-firmware-20261014.zip` 中未修改的 Ringo 驱动和 IMU / ADPCM 解码器。所需源文件保存在 `vendor/ring_studio/`；`PROVENANCE.json` 记录压缩包和每个源文件的 SHA-256，启动时验证。Qt UI 和固件升级模块不会加载，Mythlink 主项目的 SDK 不会替换。

raw 启动命令为 `21 00 c8 00 c8 00 d0 07 10 0a 00 00`，明确选择原始六轴。新实验固定请求 **200 Hz / ±16 g / ±2000 °/s / 每包 10 帧**，与新 SDK 的固定解码比例一致。收到 token 或其他编码会停止，避免误标为物理量。历史 token 实验仍可回看，始终显示 T1–T6 和未知单位。

每个 `21 02` 包包含有符号 int16 的 ax、ay、az、gx、gy、gz。加速度按 SDK 转为 m/s²；SDK 的陀螺仪 rad/s 转为本程序沿用的 °/s。原始整数完整保留，没有对保存数据做去重力、滤波、平滑或自动校准。这不证明芯片/固件内部没有滤波。

麦克风使用新 SDK 的 `20 00` 启动命令。public_dev 固件返回 ADPCM 分片，用同包 SDK 解码为 16 kHz 单声道 PCM16，不添加软件增益。完整块按序输出，缺失分片和块保留统计；连续 2 秒数字全零、断流或错误编码会停止并保留已采数据。

## 同步与回看

- 页面上方先选择历史记录，选择后自动打开完整数据；明确显示记录时间、模式、时长和样本数。刷新页面会保留链接中选中的历史记录。采集在后台完成不会覆盖正在回看的历史记录。
- 历史记录与新完成的实验共用“查看整段 / 放大 / 缩小 / 前后平移 / 起止秒数 / 拖选”按钮。自动语音片段可逐段跳转，默认带前后各 1 秒对照，可改为 0、0.5 或 2 秒。
- 停止保存或打开历史时，根据戒指 WAV 的 20 ms PCM16 帧运行 WebRTC VAD（mode 2），再用噪声底上方 6 dB 的门限抑制弱背景（门限限于 −65 至 −32 dBFS）。至少累计 180 ms 有声帧才成段，合并不超过 200 ms 的真实停顿，数据缺口和无效音频不跨越。只使用音频，不使用 IMU，也不判断本人/旁人；手部碰撞声仍可能误检。实时采集期间不显示未经完整检测的语音结论。
- 所有时域图与总览以蓝色背景标出同一批自动候选，人工条件另放在图底色条。频谱用实线表示所选区间，紫色虚线表示其中的自动语音片段；不足 256 连续样本时明确提示，不拼接不同语音段。音频偏移同步移动区间标记、跳转边界与语音子集频谱。

- IMU、戒指麦克风共用设备 uint32 毫秒 uptime 和一个主机锚点；不按各自 BLE 到达时间独立对齐。包序号、设备时间和主机接收时间一并保存。
- SDK 按 200 Hz 回填 IMU 包内时间。实际速率由相邻完整包的端点和样本数独立计算；采用累计样本 / 累计时间，避免 49/50 ms 时间戳取整造成偏差。与请求速率相差超过 5% 时停用频谱/能量分析。
- 音频按块末时间戳向前回填 PCM；固件对采样边界尚未确认，可能有约一个块（通常 100 ms）的固定偏移。回看支持 ±1000 ms 偏移，音量图、游标、播放和包络相关同时更新，原文件不变。共享时间轴不代表已验证精密硬件同步，相关延迟不能当作振动传播时间。
- 点击“整段”或双击时域图查看全程；在总览或时域图拖选放大，或输入起止秒数。加速度、角速度、音量和能量图共用范围与游标。点击固定游标，读取同一时刻六轴物理值、原始 int16 和音量。
- “播放选中片段”播放戒指录音，游标同步移动。WAV 帧位置通过 CSV 映射回设备时间；丢块不伪装为静默。
- 波形默认仅显示时去窗口均值，可关闭；比较不同片段振幅可锁定 Y 轴。绘图抽点保留极值，频谱和统计使用选区全部样本。全程条件表不会随局部缩放改变。
- 回看频谱采用连续 256 点 Hann 窗、50% 重叠平均、三轴功率求和。频率轴使用实测包时间速率，跳过数据缺口。
- 能量为 200 ms 窗口逐轴去均值后的三轴合成 RMS；图上各组独立标准化，原单位统计另列。条件表排除标签前后各 1 秒，减少点击操作干扰。
- 相关为 `corr(audio(t), IMU(t + lag))`，搜索 ±1 秒、步长 200 ms，正 lag 表示 IMU 较晚。至少 20 个有效窗口；缺音频不作为静默。最大相关没有显著性检验，不能证明身体传导。

## 保存与恢复

默认目录 `data/imu_speech_lab/<日期时间_随机后缀>/`：

| 文件 | 内容 |
| --- | --- |
| `imu.csv` | 共享时间、接收时间、设备相对时间、样本与包序号、六轴物理值、六轴原始 int16 |
| `audio.wav` | 戒指 ADPCM 解码后的 PCM16 / 16 kHz 单声道，丢块不补静音 |
| `audio.csv` | 每 20 ms 音量 RMS / peak、时间戳、WAV 帧偏移及帧数 |
| `ring_audio_blocks.csv` | 原始音频块序号、uptime、估计起止时间、样本数、累计丢块 |
| `ble_packets.jsonl` | 收发蓝牙包 hex、方向、主机相对时间，便于重新解码与核验 |
| `audio_events.csv` / `markers.json` | 音频状态与人工实验条件 |
| `metadata.json` | 固件版本、SDK 来源/哈希、配置、时间边界、流类型和丢包统计 |
| `summary.json` / `conditions.csv` | 全程条件的描述性统计 |
| `speech_segments.json` | 本地自动语音候选、检测方法和参数；独立于人工标签，历史网页回看时按现有录音重算 |
| `report.html` | 包含完整样本的离线回看；播放需同目录 `audio.wav` |

实时仅缓存最近 35 秒 IMU；正常停止后从完整 CSV 构建报告，不会丢掉早期样本。历史下拉框区分 raw、token 和音频来源。强制杀进程可能损坏 WAV 文件头；请正常停止。

```sh
python tools/imu_speech.py --port 8767 --no-browser
python tools/imu_speech.py --report ./data/imu_speech_lab/<实验目录>
```

## 实物证据与软件验证

旧固件 `1.2.133` 曾只收到 token。升级后，同一枚 Ringo8F56 报告 `2.0.2.public_dev`；单独 raw 短测收到 2,080 帧，约 202.8 Hz，没有序号缺口或 token 包。新 SDK 固定 200 Hz 配置不是 1 kHz 采集，不能据此宣称能测到所有声带频率。

```sh
.build/packaging-venv/bin/python -m pytest tests/test_imu_speech_lab.py -q
node tests/test_imu_speech_review.cjs
```

验证原始整数与物理单位、包序号/时钟回绕与缺包、ADPCM 分片重排/冲突、音频缺口与共用时钟、完整回看、FFT 功率和频率、音频偏移与播放映射。说话相关特征仍须真人实验验证；能量升高也可能来自呼吸、手部动作、空气或桌面振动。
