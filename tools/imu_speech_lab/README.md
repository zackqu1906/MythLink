# Ringo IMU Speech Lab

独立的本地实验程序，观察讲话时戒指 IMU 数据是否出现可重复的变化。默认接收与主项目触摸板完全相同的 6 通道 float16 token；也提供原始六轴 raw LSB 模式。不会启动 Mythlink 主程序、运行触摸板模型或注入鼠标动作，也不会输出“佩戴者正在说话”的判定。

token 每帧本身含 6 个数值，可以直接解码、画波形及做描述性分析。其物理单位、固件归一化/滤波尚未确认，因此显示 T1–T6、token 单位，不冒充 m/s²、°/s 或原始 ADC。T1–T3、T4–T6 只是显示分组，尚未确认分别对应哪种传感器。

## 启动

在 Finder 双击 `scripts/imu-speech-lab.command`，或在仓库根目录执行：

```sh
./scripts/imu-speech-lab.command
```

浏览器打开 `http://127.0.0.1:8766`，点击“连接并开始采集”。先在占用戒指的其他程序中断开连接。启动器优先使用项目已有的 `.build/packaging-venv`，其次 `.venv`。缺依赖时，在自己的 Python 3.11+ 虚拟环境安装 `numpy bleak sounddevice cryptography`，然后执行 `python tools/imu_speech.py`。macOS 需给运行 Python 的宿主程序蓝牙、麦克风权限。

若附近有多枚 Ringo，程序会列出名称并要求输入完整名称，不会任意连接第一枚。

可选参数：

```sh
python tools/imu_speech.py --port 8767 --no-browser --output ./data/imu_speech_lab
python tools/imu_speech.py --report ./data/imu_speech_lab/<实验目录>
```

“用合成数据检查界面”完全不连接硬件、不录音；它故意注入说话相关的 31 Hz 信号，只用于验证软件。演示数据的目录带 `_DEMO`，元数据与报告始终标明 `synthetic: true`。

## 第一次实验

1. 佩戴戒指，把手放桌面或腿上，另一只手操作界面。记录姿势、戒指到嘴的距离和松紧。
2. 默认“项目同款 token”，固定使用项目的 200 Hz / 16 g / 2000 °/s 启动参数，通道单位并不由这些参数确定。电脑麦克风提供音频参照，避免戒指音频与 IMU 争用 BLE 带宽。仅在固件支持 raw 时切换原始模式，建议从 200 Hz / ±2 g / ±250 °/s 开始。
3. 点击“开始 65 秒引导实验”：每阶段准备 3 秒，采集 10 秒，顺序为静默、自己说话、静默、长音“啊”、静默。结束自动保存。
4. 再做手动对照：静默、旁人靠近戒指说话、音箱播放、只动手、同时说话。每段至少 10 秒，按相应按钮或数字键 0–7 标记；这是人工条件标签，程序不会自动验证标签是否真实。
5. 每组至少重复 3 次，再改变手的位置、嘴的距离或佩戴松紧，分别录成新实验。

标签切换前后各 1 秒从条件统计中排除，减少操作键盘/鼠标造成的混入。手动取消引导会继续采集，必须点击“停止并保存报告”结束。网页关闭不会停止采集；关闭前请先停止，或在终端按 Ctrl+C。引导计时依赖页面，运行时保持页面打开。

## 如何读图

- 六通道波形：token 模式显示 T1–T6，单位未知；raw 模式才按请求参数换算 m/s² 和 °/s。默认仅在显示时去窗口均值，可切换看直流。显示抽点保留每通道极值；FFT 和导出仍使用收到的全部样本。比较振幅时使用“锁定波形 Y 轴”，防止自动缩放造成错觉。
- 短时能量：200 ms 窗口，每轴减去局部均值，计算三轴合成 RMS。图上各通道单独标准化，只能比较变化时序。报告提供真实单位的中位数及相对静默比值。
- 频谱：最后连续 2–4 秒，去均值、Hann 窗、单边功率谱密度，三轴功率相加；跳过缺口，不用补零或插值跨越丢包。频率到 Nyquist 上限。峰值未必是声带基频。
- 相关：`corr(audio(t), IMU(t + lag))`，搜索 ±1 秒，步长 200 ms，选最大绝对相关。正 lag 代表 IMU 较晚；少于 20 个有效能量窗口或恒定信号不报告数值。它没有显著性检验，最大值搜索本身有选择偏差，不能用于证明身体传导。
- 条件统计舍弃不完整的 IMU 窗口、缺口和标签边界。音频状态异常或不完整窗口不参与包络相关。音频缺失不会被当作静默。

## 采样率、芯片与时间边界

SDK 支持 ICM-42688 / ICM-45686 的原始 LSB 解码，默认 IMU 请求是 200 Hz。程序先读取设备 INFO，自动选择已报告的芯片；无法确认时要求手动选择，不会把 SDK 默认值写成检测结果。

500 / 1000 Hz 是实验性的固件请求，**不代表固件支持**。SDK 会根据请求速率回填包内时间，因此程序使用相邻完整包的末样本时间戳和样本数独立估算包输出速率。若它与请求差异超过 5%，暂停频谱和能量统计。有效送达速率包含丢包；它与包时间速率分开显示。采样速率匹配仍不能确认芯片内部 ODR、带宽、滤波或传感器值是否重复。

量程依 SDK 请求换算，当前协议没有实际量程回读。默认小量程便于观察微弱信号；出现近饱和值时调大量程重测。原始 LSB 会保存，方便检查量化台阶和重新换算。录制中不运行自动校准，不改变 HID 等持久设置。

IMU 的单调设备时钟用于相对时间，处理 uint32 毫秒回绕；首包接收时间减去包跨度作为主机锚点。电脑麦克风使用 PortAudio ADC 时间映射到同一主机 monotonic 轴。**不是硬件同步**：仍有未知 BLE 延迟和两套时钟的漂移，报告的 lag 不能当作机械传播时间。设备时间重复、回退、长时间中断或断连会结束当前实验，避免静默拼接不连续的数据。

## 保存内容

默认目录为 `data/imu_speech_lab/<日期时间_随机后缀>/`，已被仓库 `data/` 忽略规则覆盖。

| 文件 | 内容 |
| --- | --- |
| `imu.csv` | 估计对齐时间、接收时间、设备相对时间、样本序号、包序号、六通道；token 模式为 t1–t6 且 raw LSB 列为 NaN，raw 模式为六轴物理值与原始 LSB |
| `audio.wav` | 电脑麦克风单声道 PCM16；中断不补静音，精确文件偏移见 CSV |
| `audio.csv` | 每块 ADC 中心时间、接收时间、WAV 帧偏移、帧数、线性 RMS、peak、状态异常标志 |
| `audio_events.csv` | PortAudio overflow 等状态文字 |
| `markers.json` | 人工条件切换时间与姿势备注 |
| `metadata.json` | 配置、设备报告、请求值、时间边界、结束状态、SDK 统计 |
| `summary.json` / `conditions.csv` | 全部已标记有效片段的描述性统计；JSON 的 signals 标明 acc/gyro 字段在 token 模式只是 T1–T3 / T4–T6 分组 |
| `report.html` | 可离线打开的自包含报告；显示最后 15 秒，数据内含末 30 秒，条件统计覆盖整个实验 |

SDK 还会在同级 `sdk/` 目录保留它自己的原始 CSV（含原设备 uptime）。程序持续落盘且内存只保留最近 35 秒 IMU。正常停止后关闭 WAV 文件头并生成报告；强制杀进程可能留下不完整 WAV 文件头，原始 IMU CSV 通常仍可检查。重新生成报告用 `--report`。

## 2026-10-23 实物连接检查

现场连接到的 `Ringo8F56` 报告 `ICM42688`、硬件 v1、固件 `1.2.133`。实际比较了以下 raw 请求，均收到 `21 09 01`，没有六轴样本：

| 请求 | 量程 | 命令 |
| --- | --- | --- |
| SDK 当前 12 字节 raw，200 Hz | ±2 g / ±250 °/s | `21 00 c8 00 c8 00 fa 00 02 0a 00 00` |
| 11 字节 raw，200 Hz | ±2 g / ±250 °/s | `21 00 c8 00 c8 00 fa 00 02 0a 00` |
| 11 字节 raw，200 Hz | ±16 g / ±2000 °/s | `21 00 c8 00 c8 00 d0 07 10 0a 00` |

随后直接复用项目 `src/ring_python_sdk/touchpad/core.py` 的 `START`：`21 00 c8 00 c8 00 d0 07 10 0a 01`，以及同文件 `parse_tokens`，在同一枚戒指 3 秒内收到 58 包、580 个六通道样本，包时间约 202.85 Hz。当前程序已接入该模式；没有复制另一个 SDK 或更改主项目的 SDK。程序保存运行时 `sdk_path` 供复核。

未假定状态码 `01` 的具体定义。结论是 raw 模式尚未取到数据，项目 token 模式确实可用。可先用 token 观察讲话是否伴随变化；如需对“原始机械振动”做物理解释，仍须向固件方确认 token 的通道定义、缩放、滤波或开放 raw。不能由 raw 请求失败推断芯片本身测不到说话。本次没有刷写固件。

电脑麦克风此次短测输出全零，程序现会明确提示检查输入设备、静音与系统麦克风权限；没有将全零流当成有效音频参照。未完成真人说话的可行性验证。

“说话 / 静默”比值升高仅表示观察到差异；需要与旁人、音箱、动作控制重复比较，才能排查空气传播、呼吸和手部运动。即使合成信号检查通过，也不能声称实物戒指可测到讲话振动。
