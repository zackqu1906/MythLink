# 昇腾 Clef 常驻服务与项目接入

2026-11-04 已部署并实测。当前主项目为单次联合 `ClefIntentRouter`：总体意图＋修改、插入、润色、格式整理、翻译、按目标创作六项任务；空原文时从请求中移除修改。释字和重述并入修改，扩写及精简并入润色，格式单独保留。服务动态接收 schema，无须重载权重；最新结果见 [v19 空原文移除修改类别对照](reports/clef-schema-gate-v19-2026-11-05-comparison.html)。

## 当前连接

- 公网接口：`http://mythlink.cn:20031/v1/systemone`，无需账号登录；健康检查为同地址 `/health`。
- 2026-11-09 已确认公网 20031 对应服务器内部 20031，并将常驻服务切换到 `0.0.0.0:20031`。用户提供的可用公网端口范围为 20031–20039，客户端可按实际分配修改端口。
- 模型：`Cloudflare/clef-flash`，revision `41318bf2106d135c7a92da745fec4b255279b4de`。
- 硬件：Ascend 910B3，64 GiB HBM，逻辑设备 `npu:0`。
- 环境：Python 3.12.13、torch/torch_npu 2.10.0、Transformers 5.10.2；BF16，eager attention。
- 当前 HTTP 层不要求 Bearer token；应用直接访问公网接口，不创建 SSH 隧道。服务器代码仍支持可选 `CLEF_API_KEY`，当前无登录客户端不发送此字段。
- SSH 管理入口仍是 `root@mythlink.cn:20030`，仅用于维护；不是应用推理连接。原 `127.0.0.1:30000` 监听已替换。

模型只加载一次。加载和推理都在同一个专用线程执行，串行使用 NPU，最多容纳 4 个运行中或排队请求。`GET /health` 不等待推理队列。原部署用旧一级和二级请求预热后监听；当前评测另行预热联合请求。

接口接受 `model/state/questions`，支持文本或 JSON state 及 choice/score/noul；当前部署不接收图片、视频。请求体上限 128 KiB，最多 32 个问题，模型输入上限 8192 tokens。超长输入直接拒绝，避免上游编码器静默截断 state。日志只记录 token 数、问题数、耗时及错误类型。

## 从主项目使用

### 应用设置

设置 → 服务设置 → 自动路由服务器：服务器地址填写 `mythlink.cn`，公网端口填写 `20031`，点击“保存并测试”。此界面只保留地址与端口，验证健康接口和一条合成分类，不使用账号、私钥或开发机环境变量。旧 SSH 设置仅沿用地址，端口改为 20031；新设置保存到 `clef/http/*`。网络失败、错误端口和推理失败会显示在设置中。

这是 2026-11-09 的源码变更，旧安装包仍是 SSH 界面，需重新构建安装。新安装或更新后还应安装/更新随包提供的输入法组件。

### 开发工具

在项目根目录直接访问公网服务，例如：

```bash
export PROXIMIC_CLEF_URL=http://mythlink.cn:20031/v1/systemone
export NO_PROXY=mythlink.cn,127.0.0.1,localhost
export no_proxy="$NO_PROXY"
curl --noproxy '*' --fail http://mythlink.cn:20031/health
.runtime/venv/bin/python tools/check_clef_router.py --output .runtime/clef/routing-evaluation.json
bash scripts/start-ui.sh
```

`check_clef_router.py` 支持 `--cases` 选择样例文件及 `--case` 指定单条样例。`check_clef_pipeline.py` 读取本机主项目已有文本模型配置，通过真实 `TextProcessingWorker` 运行分类及后续生成，不写入其他应用。

源码主项目优先使用界面保存的公网配置；未配置地址时，开发命令仍支持 `PROXIMIC_CLEF_URL`。实际使用自动语音时，在“输入与控制”选择“自动判断”。

`scripts/clef-remote.sh` 保留为旧 SSH 开发辅助脚本，不参与应用的公网连接。若继续使用它，需将未入库的 `.runtime/clef/connection.env` 中 `PROXIMIC_CLEF_REMOTE_PORT` 改为 20031 并重建旧隧道；下方历史报告中的 SSH 命令对应当时部署。

## 服务器管理

部署文件位于 `/root/clef-test/`，包含 `serve_clef_npu.py`、`clef-service.sh`、`warmup.json`。

在服务器上运行：

```bash
bash /root/clef-test/clef-service.sh status
bash /root/clef-test/clef-service.sh start
tail -f /root/clef-test/service.log
# 需要停止时：
bash /root/clef-test/clef-service.sh stop
```

启动脚本默认 `CLEF_BIND_HOST=0.0.0.0`、`CLEF_PORT=20031`；服务程序新增 `--host` 参数，单独运行时仍默认回环监听。该容器 PID 1 是 sshd；当前使用 nohup 常驻，可跨 SSH 断线继续运行。它不是开机自启或崩溃自动重启的系统服务：容器重启或服务退出后需要重新执行 start。

### 首次部署基线：v2 的 32 条分类样例

| 项目 | 结果 |
| --- | --- |
| 网络、HTTP 或模型执行故障 | 0 |
| 一级听写/编辑正确 | 27/32（84.4%） |
| 完整任务及辅助标签精确匹配 | 15/32（46.9%） |
| 空编辑计划被客户端拒绝 | 1 |
| 8 条听写中的一级误判编辑 | 4，其中 1 条在二级被拦截；3 条返回了错误编辑计划 |
| 分类总耗时 median / P95 | 1.548 s / 1.790 s |

耗时包含本机客户端、SSH 转发及条件性的两个 HTTP 请求；这些是单客户端、串行、小样例的结果，不是并发容量指标。现有测试工具的 `errors=1` 是空编辑计划校验失败，不是服务连接失败；`false_edit_count=3` 只统计最终返回编辑计划的情况。

代表性问题：

- “他说把上一句删掉就可以了”被当作精确删除命令。
- “翻译成英文”在存在原文时仍被分到听写。
- 插入、扩写、润色、结构调整经常额外命中 `precise_edit`。
- “周四下午”能识别为编辑，但漏掉直接重述辅助标签。
- 带有 OCR 干扰指令的“我收到了”被一级判为编辑，随后因所有编辑任务为 skip 被客户端拦截。

这些现象表明服务及接口可用，但该轮分类效果尚不能作为自动编辑质量验收通过。该轮使用原有 v2 提示词；后续一级改进见下文。

### 真实 Worker → Clef → 已配置文本模型

7 条合成样例中，6 条完成实际文本模型调用并返回正文；1 条空编辑计划被拦截，未进入生成。生成服务使用主项目已有配置 `deepseek-v4-1-flash-260910`。6 条完成调用的总耗时约 1.54–2.66 秒。

- 精确修改：`我今天想喝咖啡。` + “把咖啡改成牛奶” → `我今天想喝牛奶。`
- 听写：“我明天下午到了给你发消息” → `我明天下午到了给你发消息。`
- 插入：返回 `请明天提交。谢谢配合`，但分类计划额外包含精确修改。
- 翻译：虽然文本模型返回了英文，Clef 实际路由为听写，不能据此判定自动编辑流程语义正确；应用的听写交付方式不同于编辑替换。
- 混合修改与润色：标签正确，但生成的 `麻烦请您让张玮明天把文件给我。` 引入了“让某人转告”的潜在语义变化，需继续评测生成质量。

这次验证的是源码客户端、HTTP 服务及文本处理 Worker 的软件链路。未采集真实麦克风/戒指输入、未做实时 OCR、未写入输入框或向聊天应用发送消息，因此不覆盖完整物理设备和输入法写回验收。

### 听写选项定义调整（旧 v9 基线）

`voice-intent-joint-v9-dictation` 仅修改 `CLEF_ROUTING_CRITERIA["dictation"]` 的文字，另更新版本号：明确转述建议、评价和个人未来计划中提及的操作不自动成为编辑委托；原文适合处理也不足以改变这个判断。保留实际委托及更新本人已有输入的边界。总体 edit 选项、共享规则、七类任务定义、判定阈值与生成提示词均未改动。

`tools/clef_split_routing.py` 从当前提示词模块复用共同意图边界、总体 criteria、六类 description/criteria 与组合规则，使用原 `available_edit_tasks` / `resolve_joint_decision`。总体请求只包含一个问题，并在 state 提供可用类别的简短定义；细分请求包含六类（空原文为五类），假设编辑进行预计算，允许转述、照录等正文全部 skip。不复制或回退到旧版 modify 边界。
