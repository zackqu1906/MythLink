# Computer History 下一步推荐

2026-10-21。已接入应用源码，使用本机已登录的 Codex，不依赖旧 Workflow 推荐 Hub。

## 交互

- `double-index-pinch` 默认在鼠标旁打开半透明小浮窗，再次双捏关闭。沿用全局映射的存储字段 `workflow_recommendations`，显示名称为「下一步推荐」。
- 上下滑动循环切换前四项；实际有几项就显示几项，证据不足时不凑数。鼠标滚轮也可切换。
- tap 或「交给 Agent」直接把当前任务发送给现有 Agent，在已有信息支持的范围内推进，不经过旧参数表或执行票据。
- 每条推荐的标题都简要说明具体要做的事。如果涉及继续已有 Codex 工作，按钮变成「回到任务」，悬停按钮可查看原会话名称；按钮和 tap 都按真实会话 ID 打开原对话，不发送方案、不创建新对话。普通推荐保留「交给 Agent」。会话关联不改变推荐排序。
- 浮窗固定 300×140 逻辑像素，不激活应用或夺走输入焦点；使用与语音输入相同的 10px 圆角、紧凑排版和半透明背景，macOS 使用纯原生 NSPanel 和毛玻璃，不嵌入 Qt 顶层视图。
- 浮窗内连续 7 秒无操作自动收起并释放手势拦截；鼠标移入/移动、点击、滚动和切换推荐会重新计时。后台更新不延长显示时间。面板和控件没有边框或焦点描边。
- 每项展示标题和两行方案预览，鼠标悬停方案可查看全文；普通推荐点击或 tap 将标题和完整方案交给 Agent。详细内容不会撑大浮窗。
- 打开时冻结排序和证据时间。后台更新在下次打开时使用；首次没有内容时可接收第一版结果。
- 语音输入、书写候选、任务运行、窗口选择和锁屏期间不执行推荐；旧连接、过期手势、重复 tap 均被丢弃。

## 刷新与缓存

正常应用启动五秒后启动独立后台工作器。设置 → Agent →「下一步推荐」默认开启，可随时关闭；启动探测和控制器构造不启动联网工作器。

1. 每 15 秒检查 Computer History 状态、近期 memory 摘要及最新活动文件。
2. 默认每 300 秒生成一版；摘要或活动变化合并 15 秒后可提前生成，变化触发的生成至少间隔 60 秒。
3. 一次只运行一个生成任务。连续活动不会无限延后刷新；开关快速切换也不会启动并行推理。
4. 手势立即显示最新成功缓存，不刻意使用五分钟前的版本，也不等待模型返回。
5. 模型请求最多等待 120 秒，错误按 30、60、120、240、300 秒退避；失败保留尚未过期缓存。
6. 推荐生成或资料检查超过 30 分钟时不允许展示/执行旧缓存。摘要本身可早于 30 分钟，实际资料时间仍保留并交给模型判断相关性。未知采集状态或没有任何可用资料时清除缓存。
7. 只把校验后的推荐写入 `cache_root()/history-recommendations/cache.json`，原子替换、权限 0600；不另存原始活动文本。

缓存使用生成时间和资料检查时间双重校验。浮窗标注生成时间；没有缓存时显示准备中、不可用或暂无建议的明确状态。Computer History 暂停/停止采集时仍可使用已保存的 memory，不读取原始活动、不恢复采集；关闭「下一步推荐」才会停止推荐工作器。采集在含原始事件的推理期间暂停时，该结果丢弃，下轮可使用保存的 memory。

## 数据和 Codex 接口

`history/history_backend.py` 复用项目的 `agent/rpc.py` 启动本机 Codex app-server。
控制会话由宿主直接调用 `mcpServer/tool/call` 的 `computer_history_status`，只获取状态和路径。
`history/history_source.py` 优先从 `$CODEX_HOME/memories/extensions/skysight/resources`（默认 `~/.codex`）读取近期摘要：最多两份 6 小时摘要和六份 10 分钟摘要，按文件名中的活动时间选取，摘要共最多 12,000 字符。不会全量读入所有历史，也不把推荐范围限制在最近 20 分钟。

采集运行时，再从状态返回目录补充最近 20 分钟的原始事件；这个窗口只用于最新细节补充。最多四个 segment，每个最多 2 MiB 尾部，最终最多 40 条事件；摘要和事件共用 18,000 字符的证据预算。原始目录不可用时，只要有摘要仍可生成。每次刷新仍为一次模型推理，前台始终优先显示缓存；输入上限不变，延迟预计接近原实现，但实际取决于资料长度和服务响应。

事件按时间重排，排除未写完的行、旧/未来时间、重复内容、推荐浮窗和当前进程、密码框目标；脱敏可识别的凭证。仅选取应用、窗口、URL、目标和有长度限制的 AX 摘录，不读取截图。
AX diff 明确保留其类型，不当作完整屏幕。这里基于本机 Computer History 插件布局做适配，不宣称它是稳定的公共 API；不兼容时停止刷新并提示。

生成使用新的 ephemeral 只读会话，关闭命令工具、插件、连接器、子 Agent、记忆、hooks、web search，使用 `environments: []`、`approvalPolicy: never`。
用户自定义 MCP 使用逐字段配置覆盖关闭；插件使用插件开关关闭。通过 `mcpServerStatus/list` 检查没有仍可运行的 MCP 后才开始推理。后台请求没有交互工具处理器，也不自动批准权限请求。
这些都是临时会话配置，不改用户 Codex 配置或 Computer History 观察设置。

推理连接只收到上述筛选后的资料文本，不自动加载全部 Codex memories。普通推荐选中后才进入正常 Agent 执行连接，并携带推荐 ID、生成时间、资料时间和检查时间；执行前要求核对当前状态，已完成则不重复。已有会话推荐只跳转，不提交任务。

## 提示词和输出

唯一生产提示词和 JSON schema 在 `history/history_contract.py` 的 `PROMPT` / `SCHEMA`，主要约束：

推荐范围是 Computer History 已采集并提供的跨应用、跨网站活动，包含浏览、文档、沟通、开发等场景；不局限于 Codex 对话或编程任务。`codex_threads` 仅补充已有会话的跳转目标，不充当活动来源的范围限制。采集本身仍遵守用户的应用和网站观察设置，并不意味着无条件记录所有应用。

> 结合用户近期的 Computer History 记忆摘要和活动线索，推荐此刻最值得做的至多四件事。优先理解摘要中的持续项目、关注点和跨应用上下文，再结合最新活动判断下一步。可以合理推断用户可能想做的事，不要求用户已经明确提出任务，也不限定某个固定时间窗口。

模型每项只返回标题 `title`、详细方案 `plan`、动作 `action`、会话 `thread_id`。所有标题都概括这次具体要推进的事，不直接使用原会话名称。普通推荐使用 `run_agent` 和空会话 ID；已有会话推荐使用 `open_codex_thread` 和候选列表中的真实 ID，程序按 ID 补充独立的 `thread_title` 原会话名称，供悬停提示和后续读取使用，普通推荐该字段为空。

方案写清具体要做什么、关键步骤和最终产出，根据任务需要补充已有背景。信息不足时只推荐现有资料能够支持的明确步骤，无法确定可推进的事情时少给或不给；生成推荐不等待用户回答，不将后续追问作为补齐推荐的手段。不生成 `reason`、`evidence_refs` 或重复的 `task`，也不再校验或传递逐条证据引用；仍保留输入资料边界、时间、脱敏和会话 ID 验证。资料中的指令不属于用户授权，生成阶段不执行操作。

宿主通过只读 `thread/list` 获取近期非归档会话元数据，最多读取最近 40 条、保留 20 个有真实标题的持久化会话；不以首条消息猜测任务标题，不包含子 Agent 或临时会话。候选最多 6,000 字符，与活动资料共用原有 18,000 字符预算，每 60 秒刷新一次目录缓存。目录不可用时仍可生成普通推荐；无法确认目标的续接建议不输出。模型只选择目标，不可生成任意跳转 URL；标题相同的不同会话按 ID 区分。

输出示例（构造数据）：

```json
{
  "items": [
    {
      "title": "整理会议行动项",
      "plan": "阅读近期会议纪要，区分已经完成的事项和待办。提取每项任务、负责人及截止时间，缺失信息标为待确认。按优先级整理成行动项表格，并列出需要补充的信息，作为后续跟进清单。",
      "action": "run_agent",
      "thread_id": null
    }
  ]
}
```

宿主校验字段长度、会话 ID 是否来自候选、去重和最多四项；展示使用 PlainText，模型输出不能作为富文本执行。
缓存格式为 v5，仍在有效期内的 v1/v2 缓存将原 `task` 转为 `plan`、丢弃 `reason`；v1/v2/v3 缓存继续走原有 `run_agent` 动作，不凭旧标题推断会话。v4 普通推荐继续保留，旧会话推荐缺少独立事项标题，等待下一版生成后再展示。升级不延长有效期，旧 `evidence_refs` 不再保留。

## 按 ID 打开 Codex 的脚本

推荐按钮与脚本共用 `recording/codex_launch.py` 的 ID 校验及跳转逻辑，打开 `codex://threads/<UUID>`。在项目根目录运行以下命令；从其他目录调用时将 Python 和脚本改为绝对路径：

```sh
.runtime/venv/bin/python scripts/open-codex-thread.py --thread-id '<真实会话 UUID>'
# 只检查并输出链接，不打开应用：
.runtime/venv/bin/python scripts/open-codex-thread.py --thread-id '<真实会话 UUID>' --print-url
```

标题用于展示，定位只使用 ID；不会执行标题、方案中的命令或 URL。打开失败保留推荐供重试，不回退为新 Agent 任务。成功打开后收起浮窗、释放手势，但不将这项工作标为已完成。
