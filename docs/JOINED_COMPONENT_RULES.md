# 按部件统一连笔规则（2026-10-30）

## 本次修正

旧版把反、白、了、子、衤作为固定起点，轨迹模型文件同时携带当时生成的字表；反的样本可以触发备选，但斤没有对应登记。解码器还固定每字最多一次、每次恰好两笔，因此也不能组合处理近中的两处连笔。

现在将部件规则、部件位置与个人轨迹模板分离。厂形部件的平撇／双撇写法由同一条规则处理，反、斤及听、新、所、近中的相同部件都会继承，按当前字典的合法笔序展开。运行时加载旧70条模型也会使用最新的部件位置表，不必重新采原来的数据。

**走之底按用户确认的方式实现：第一点单独写，只将第二笔折和第三笔捺合为一笔，展开为`zn`。不将整个走之底一笔展开成`nzn`，不补出省略的第一点。**

## 统一登记的数据

规则文件：`src/proximic_ring/assets/stroke-joined-rules.json`。每条规则记录稳定ID、部件形态、局部笔画索引、可展开的五类码和轨迹家族。旧的`fan/de`只是兼容已有样本的轨迹家族ID，不再决定哪些整字可用。

|规则|部件内可连写的笔画|编码|字例|
|---|---|---|---|
|厂形／双撇起笔|该部件两笔|`pp`，或字典允许的`hp`|反、斤、听、新、所、近、质、盾|
|白部件起笔|第1、2笔|`ps`|白、的、拍、怕|
|了／子起笔|第1、2笔|`zs/zz`，以字典保留版本为准|了、子、好、字、学|
|衤末段|第4、5笔|`pn`|补、被、初|
|走之末段|第2、3笔；第1点保留|`zn`|过、近、这、进、远、返|

构建器`tools/build_joined_components.py`递归读取部件分解与每笔归属，再映射到整字。只接受连续、来源笔数相符且能匹配当前词库编码的局部片段，不因为字符串中出现`pp`或`pn`就猜测部件。规则登记一次，包含该部件的字随构建自动继承。

生成文件`src/proximic_ring/assets/stroke-joined-components.json.gz`目前覆盖870个字符（各家族有重叠）：厂形508、白98、了／子101、衤52、走之137。源分解存在未知片段的字继续保留原识别，例如后的源数据是`⿸？口`，本轮不靠五类前缀猜它的部件。

已有的逐笔组件换序模型仍按自身规则工作，本次没有改写其规则表。连笔路径可复用它提供的调度和参考笔画映射，例如先写走之（点单独、末两笔连写）再写内部，仍能将字形进度画在正确位置。它不是将所有部件默认改为一笔。

## 解码与显示

- 一次真实落笔仍只有一条证据和一条原始轨迹；候选路径记录它展开成哪些逻辑笔画。
- 同字最多3处连笔、每步最多24条解释路径；多个连笔必须同时属于同一字典变体，先交集筛选部件归属再匹配，不扩大为任意插笔。
- 逻辑位置随着前面已展开的连笔变化，不能再用物理落笔序号直接当字典索引。
- 近的写法可为：前两撇连写、横、竖、走之第一点、走之末两笔连写。5次落笔对应7笔，映射为`[0,0,1,2,3,4,4]`。
- 退一次只撤回最后一次落笔：撤掉走之末段时，其第一点仍保留；再退一次才撤掉该点。清空和提交时一同清理。
- 候选图依据实际路径显示`连笔1→2`或`连笔2处`。若结合组件次序调度，使用显式参考索引绘制，不按笔数硬对齐。
- 保留原首候选和候选显示上限；最多预留两个连笔备选。同一家族不同编码也参与挑选，避免较常见的厂形`hp`候选吞掉斤的`pp`解释。
- 正常单笔解释、手动输入锁定、连笔不进入单笔个人学习，以及一次显示候选模式继续保留。

## 走之的识别来源与补采

当前没有走之末两笔的个人戒指样本。先从过、近、这、进、远、返的已有字形数据提取**仅第二、三笔**，生成6条参考轨迹用于提出备选；它们不是用户采集样本，也没有走之实写准确率结论。`referenceOnlyFamilies`在模型快照中明确标记walk。

重新打开完整测试程序即可先试此备选；第一点必须单独写。补采入口仍为`scripts/collect-joined-strokes.cmd`：新建v3只采走之末两笔，默认两轮26条，可先设一轮13条。每轮包括过／近／这语境下的自然、小幅、快写共9条，以及捺、横折折撇、横撇弯钩、撇点4条对照。提示明确不写第一点，旧v1/v2记录仍按原计划续采，不必重采旧70条。

## 构建与验证

```powershell
.runtime\venv\Scripts\python.exe tools\build_joined_components.py
.runtime\venv\Scripts\python.exe tools\build_joined_stroke_model.py
.runtime\venv\Scripts\python.exe -m pytest tests\test_stroke_joined_components.py tests\test_stroke_joined.py tests\test_joined_stroke_collection.py
```

第一步只更新部件编码／位置和参考轨迹；第二步才读取个人采样构建轨迹模型。已有本地模型无需重建即可加载新部件表。原70条逐轮检查在新部件表下仍保留30/30正确连笔家族，整字理想剩余笔画回放目标仍全部进入前五；这不等于新部件或走之的独立实写准确率。

测试覆盖厂形在斤／听／新／所中的继承、近的两处连笔、走之先写调度、第一点缺失时不补点、撤回末段保留点、字形映射、旧模型自动升级、旧采集续采及普通单笔保护。
