# 连续笔画测试程序整合方案与实现

本文说明主程序与连续笔画测试程序的功能边界和模块结构。

## 功能边界

主程序的「平面触控 → 笔画输入」接入连续书写、DTW 与模糊候选、逐笔字形、个人写法学习、停留方向选字、标点、退笔/删字及清空笔画。点击「开始试写」复用当前 Ring 连接，不再启动第二个设备客户端。

**按用户要求，主程序不接入 Qwen 大模型联想。** 候选依靠本地字典、离线上下文和个人写法；不会因笔画输入触发 Qwen 预测请求。独立测试程序原有的 Qwen 实验仍可单独运行。现有语音文本处理功能不在此次笔画整合范围内。

试写实验的计时评分、实验报告、连笔模型与整字纠错开关仍保留在独立测试工具中，本轮主程序先接入日常书写所需的稳定路径。

## 模块与会话

- 识别与轨迹策略统一放在 `src/proximic_ring/touchpad/stroke/`。
- `stroke_menu.py` 提供六候选与三个标点的方向映射，独立工具和主程序共同使用，避免规则分叉。
- `TouchpadController` 统一管理现有 BLE 数据流、鼠标/笔画切换及语音互斥；`StrokeSessionController` 负责目标输入框生命周期。
- 程序内书写使用六候选，中心为首选，其余在左、右、左下、下、右下；左上、上、右上分别输入逗号、句号、问号。外部 macOS 候选继续使用原有五候选协议。
- 本地确认以完整接触轨迹为准，带连续点击保护；同一动作的固件 tap 不再重复提交。后台、过期、缺帧与旧输出事件被丢弃。

## 麦克风与远端语音

```mermaid
flowchart LR
    A[请求开启触摸板] --> B[关闭语音入口并取消当前句]
    B --> C[停止 Ring 或电脑麦克风采集]
    C --> D[清空旧音频缓冲]
    D --> E[启动触摸板数据流]
    E --> F[停止 / 失败 / 断连]
    F --> G[按连接状态及原语音设置恢复]
```

GUI 在开启时清除识别事件并设置取消标记。BLE 线程在发送触摸板 START 前等待电脑麦克风停采，并停止 Ring 麦克风。音频工作线程在触摸板期间跳过读取、检测及 ASR 投递，取消未完成任务，保持手势连接。

电脑麦克风使用 PortAudio abort 暂停；清空已读余量和队列，恢复时重置重采样状态。采集代次阻止暂停前的半块音频混入恢复后的读取。即使触摸板启动失败发生得很快、音频线程尚未观察到触摸板状态，也会根据麦克风自身的暂停状态恢复采集。断连时直接关闭，不重启采集。

这里的远端限制针对新增音频推送；开始前已送达服务端的内容无法撤回。

## 比例、窗口与 DPI

采用 Qt 逻辑像素，不对整页做等比缩放。字体和操作区域保持可读尺寸；字形用正方形容器及 `PreserveAspectFit`，轨迹使用归一化坐标且不更改识别输入。

工作区宽度达到 960 时，候选与设置并排；较窄时纵向堆叠。候选区最大宽度 480，按钮和设置组按可用宽度换行。纵向滚动关闭回弹，主窗口最小高度降为 560，以适应缩放后的短屏。375 宽度是独立组件压力测试；完整桌面程序仍保留 940 的最小窗口宽度。

## UI 设计记录

使用 `refactoring-ui`，技术栈是 PySide6/QML，沿用 `FigmaTheme`、Figma 按钮和字体资源，无 Tailwind、无新增组件库，保持现有浅色模式。

| 严重度 | 问题 | 规则 | 改动 |
| --- | --- | --- | --- |
| P0 | 固定横排在窄宽度下溢出，短屏操作不易到达 | §3.3 / §3.4 | 自适应栅格、换行和垂直滚动 |
| P1 | 多个主按钮与设置抢占书写区的注意力 | §2.1 / §2.8 | 当前区域保留一个主要开始操作，导航和设置降为次级 |
| P1 | 桌面上设置挤到页面下方，左右空间闲置 | §3.3.2 / §3.6 | 宽屏双栏，候选与设置分组 |

已使用主程序的 Material 样式渲染 1280×900、1024×600、375×812；另验证 125% 和 150% 缩放。顶部/底部截图与完整主窗口截图保存到 `outputs/touchpad-integration/`。正文颜色在面板上的对比度为 6.11:1，主按钮文字为 10.63:1。
