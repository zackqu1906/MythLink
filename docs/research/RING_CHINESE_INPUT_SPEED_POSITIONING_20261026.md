# 戒指中文输入：25 汉字／分钟的比较依据与效率定位

调研日期：2026-10-26。

研究范围：戒指上的中文文本输入、极小输入面、单手与指尖输入。不把语音作为系统组成、相关方案或实验基线。引用 Ruan 等的双语研究时，只使用其计量方法、平行短语和键盘输入结果。

## 1. 当前判断

按用户提供的信息，本系统在**一名熟练用户**上达到平均约 **25 个中文汉字／分钟**。用户进一步说明：这包含相当比例的联想选字，并非每个字都通过笔画手写输入。因此该数字应标为“笔画与联想选字结合的完整系统速度”，不能标为“纯笔画手写速度”。这是一项用户报告的熟练使用表现，本轮没有读取原始计时日志。训练时长、测试材料、错误率，以及计时是否完整覆盖选字、翻页和纠错，尚未确认。

这一结果可以作为熟练使用可行性的初步证据。按已有中英文研究的一种口径，25 汉字／分钟约为 16.7 中文词／分钟，处于部分指尖／微手势英文输入工作报告的速度量级。它不能单独建立跨语言速度优势，也不足以证明普通用户能达到该水平。

最值得建立的效率论证是：**在相同戒指输入面、单手条件和中文任务下，相比经过合理优化的替代编码／选键策略，本系统是否降低完成时间与纠错成本。**

## 2. 中文 CPM 与英文 WPM 应如何比较

### 2.1 有直接文献先例的换算

Ruan、Wobbrock、Liou、Ng、Landay 的 IMWUT 2017 论文在第 3.6.1 节定义：

\[
WPM = \frac{|T|-1}{t}\times 60\times\frac{1}{L}
\]

其中英文采用 \(L=5\) 个字符／词，中文采用 \(L=1.5\) 个汉字／词。因此，若 25 CPM 的计时和字符口径与之兼容：

\[
25/1.5\approx16.7\quad\text{中文词／分钟（沿用该文口径）}
\]

这个数只能叫作“按该文定义换算的中文 WPM”。**不能称作已经实测的英文 WPM，也不能称作跨语言语义效率的等值。** 中文分词、英文标准词、短语长度、候选操作和语言熟练度均可能不同。

同样，不能直接拿 25 个汉字／分钟与 13.3 个英文标准词／分钟相除得出性能增益。若统一按 5 个书面字符作为一个标准单位，25 CPM 在算术上是 5 个此类单位／分钟，但这种单位只统一了字符数量，并没有统一中英文承载的内容。

来源：[Ruan 等原文，第 3.6.1 节](https://faculty.washington.edu/wobbrock/pubs/ubicomp-17.pdf)，DOI：10.1145/3161187。

### 2.2 比固定换算更合适的方法

1. **同语言直接比较**：所有输入法均完成同一组中文任务，以汉字 CPM、错误率和完成时间为主指标。这是本项目最强的比较方式。
2. **平行材料的完成时间**：若需要研究中英文差异，使用语义对应的中英文短语，比较各自完成整条内容所需时间，同时控制语言熟练度。Ruan 等公开了 120 对中英文短语。
3. **相对常规输入基线的保留率**：同一用户用戒指和其常规输入法完成匹配材料，计算 `戒指速度 / 常规输入速度`。可描述硬件约束下的效率损失，但跨论文保留率仍受参与者、任务与软件影响。

Ruan 等的平行材料中，英文短语平均 26.8 字符，中文平均 7.7 汉字，已经说明书面字符数不能直接代表相同内容。也不应把这组材料的长度比当作所有中英文文本的固定比例；短语计时是否减去首字符还会影响结果。

来源：[平行短语下载页](https://hci.stanford.edu/research/speech/dataset.html)、[英文集](https://hci.stanford.edu/research/speech/dataset/english-shuf-120.txt)、[中文集](https://hci.stanford.edu/research/speech/dataset/chinese-shuf-120.txt)。

### 2.3 另外两项评价方法资料

- **Text Entry Throughput: Towards Unifying Speed and Accuracy in a Single Performance Metric，CHI 2019**：Zhang、Zhai、Wobbrock 提出基于信息论的 throughput，把速度与未纠正错误纳入同一评价。其验证针对英文键盘，中文被列为未来研究方向。因此可参考其速度—准确率框架，不能把它当作已经验证的中英文固定换算。[原文](https://faculty.uw.edu/wobbrock/pubs/chi-19.03.pdf)，DOI：10.1145/3290605.3300866。
- **Multilingual Phrase Sampling for Text Entry Evaluations，IJHCS 2018**：Franco-Salvador、Leiva 研究多语言材料的可记忆性、代表性和语义，提醒实验材料与语言熟练度会影响输入结果。[作者原文](https://luis.leiva.name/web/docs/papers/kaps-ijhcs18-preprint.pdf)，DOI：10.1016/j.ijhcs.2018.01.006。

本轮未找到足以支持“一汉字恒等于若干英文词”或“中文输入普遍比英文慢固定百分比”的通用依据。也不建议用字符集大小的 `log2` 比值直接包装信息吞吐量优势，因为自然语言频率、上下文冗余和错误分布并未因此得到控制。

## 4. 中文数据能提供什么参照

### 4.1 常规手机输入：不支持“25 CPM 普遍快于拼音”

Ruan 等 2017 年双语研究的手机键盘条件中，中文为 42.83 WPM，按该文 1.5 汉字／词的口径，对应约 **64.2 汉字／分钟**。英文键盘为 52.24 WPM。这里只使用键盘条件。

这是特定材料、用户、手机和理想实验条件下的数据，不是当前所有中文用户的平均速度；但足以说明：不能凭 25 CPM 宣称优于普通手机拼音。

来源：[原文表 3 与第 3.6.1 节](https://faculty.washington.edu/wobbrock/pubs/ubicomp-17.pdf)。

### 4.2 中文 MR 手写：可作为背景，但不是同条件基线

InkFlow（CHI 2026）的中文连续手写闭环研究中，InkFlow 为 **15.21 CPM**，Pinch-Release 为 **10.03 CPM**。从数值看，本系统报告的 25 CPM 更高。

然而，该实验主要评价空间手写笔画产出，标准文本识别另作离线评价；硬件、动作尺度、用户与训练条件也不同。因此可用于介绍中文受限输入的研究背景，不应写成“本系统比 InkFlow 提升 64.4%”的受控效率结论。

来源：[InkFlow 原文，第 8 节、表 4 与第 8.3 节](https://doi.org/10.1145/3772318.3790596)。

### 4.3 不宜采用的弱对照

- OHAI（2004）报告约 16 CPM 是练习 100 小时后的模型预测，并非该训练量下的实测结果；不建议据此宣传本系统的实测速度优势。[原文摘要](https://journals.sagepub.com/doi/pdf/10.1177/154193120404800510?download=true)
- 较早手机笔画／部件工作在设备、材料和计量上差异很大。不能因为其 CPM 较低就选为主要对照，也不能仅凭同为五类笔画而认为条件相同。
- 本轮没有找到可直接替代同条件真人实验的、成熟“单戒指中文输入速度排行榜”。检索结果不足不代表此前没有任何中文戒指工作。

## 5. 目前可以写到哪一步

| 主张 | 当前能否支持 | 还缺什么 |
| --- | --- | --- |
| 一名熟练用户平均达到约 25 汉字／分钟 | 可以作为用户报告的初步观察 | 日志、材料、时长、错误率与计时定义 |
| 在极小面积条件下具有值得进一步验证的输入效率 | 有理由作为研究动机 | 多用户结果与同约束基线 |
| 按既有口径归一后，与部分英文指尖输入结果处于相近量级 | 可以作为谨慎的描述性背景 | 明确不是英语实测，也不代表统计优势 |
| 比所有戒指／可穿戴输入更快 | 不支持 | 已有更高英文速度，且语言与约束不同 |
| 比普通手机中文拼音更快 | 不支持 | 当前文献已有明显更高的手机中文速度 |
| 同约束下，比拼音选键或分区笔画更快 | 有希望通过实验建立，尚未证明 | 相同硬件、中文材料、练习量、纠错规则的直接比较 |
| 短文本任务总时间更低 | 可作为待检验假设 | 真实的准备、唤起、输入、确认与返回任务时间 |

### 现阶段建议表述

> 初步熟练使用观察中，一名用户的平均中文输入速度约为 25 汉字／分钟。这表明在戒指输入面上完成连续中文输入具有可行性。与既有极小面积文本输入文献的描述性比较显示，该表现值得进一步开展同约束、多用户评价。

对应英文可写：

> Preliminary observations from one experienced user indicate an average entry rate of approximately 25 Chinese characters per minute. This result motivates a controlled, multi-user evaluation of Chinese text entry on a ring-sized input surface.

在确认输入计时覆盖、任务类型和错误率之前，不添加 “including all corrections”“eyes-free”“in the wild”“outperforms” 等尚未得到证实的限定或结论。

## 6. 最容易建立扎实优势的实验

### 6.1 优先比较三个条件

| 条件 | 设计 | 想回答的问题 |
| --- | --- | --- |
| A：本系统 | 戒指笔画手势、现有候选流程 | 完整交互的最终效率 |
| B：同戒指分区笔画选键 | 相同五类笔画、字典、候选与确认流程，改用五区域选键；布局需先调优 | 优势是否来自轨迹／笔形动作，而非更好的字典 |
| C：同戒指拼音选键 | 合理适配的 T9／分组选字母方案，加中文拼音引擎及完整候选操作 | 形码在同一小输入面上是否比音码更高效 |

可增加普通手机拼音作为用户熟悉输入方式的参照，用来量化便携约束的代价。若要证明短时任务效率，再把拿出手机／切换输入与收起返回的时间纳入独立情境实验。普通手机条件不应被故意限制到不自然的输入方式。

输入法不同造成的候选算法差异应说明清楚：纯动作比较尽量共用解码和候选；完整系统比较则允许各方案合理优化，并单独报告差异。拼音基线必须能真正完成中文选字，不能只实现输入拉丁字母部分。

### 6.2 测量和材料

- **计时边界**：完整任务从第一次输入动作开始，到最后确认提交结束；含画笔画／按字母、候选等待、选字、翻页和纠错。不能仅从首个汉字上屏开始，因为这可能排除第一字的大量编码时间。若另报文献常用首字符计时，分开命名与计算。
- **主指标**：中文 CPM、单条任务完成时间、最终未纠正 CER；另报总错误、纠错耗时、候选翻页和选择次数。分清“尝试输出字符数”与“最终正确文本”，不要只报告动作识别率。
- **材料**：未见过的自然短句，覆盖高频日常表达；再加入专名、较复杂字形和罕见搭配。新手熟悉材料与正式测试材料分离，系统调参与测试短语分离。
- **参与者**：将当前熟练用户作为独立熟练案例；再招募多名母语中文用户做被试内比较。12—20 人可作为初步招募规划范围，正式数量依据先导差异和变异度做功效分析。
- **练习**：既看相同练习量下的学习曲线，也看趋于稳定后的表现；不能让本系统的开发者与基线的新手作直接比较。
- **分析**：报告每位用户、组均值、变异与区间；多条短语不是多名参与者，不能把单人几十条试次当作几十人的证据。必要时使用参与者和短语层面的模型。

### 6.3 优势大小如何解释

以下只是以 25 CPM 为固定假设值的数学示例，**不是已经获得的基线实验结果**。

| 同条件中文基线速度 | 本系统速度提升 | 完成相同长度文本的纯输入时间下降 |
| --- | --- | --- |
| 15 CPM | 66.7% | 40.0% |
| 20 CPM | 25.0% | 20.0% |
| 22 CPM | 13.6% | 12.0% |

例如，若经过公平训练后的同戒指中文基线为 20 CPM，而本系统组均值仍为 25 CPM，且错误率没有增加，那么“速率提高 25%、同长度纯输入时间减少 20%”就是直接且容易解释的效率结果。显著性与区间仍需真实数据。

## 7. 短文本的端到端效率可能是另一个优势

完整任务耗时可以建模为：

\[
T = t_0 + \frac{60n}{v}
\]

其中 \(t_0\) 包含准备、唤起与必要的结束操作，\(n\) 为汉字数，\(v\) 为包含选字与纠错的 CPM。若与手机比较，还须计入设备取用、输入焦点获取与文本传输等实际发生的步骤。

**仅作假设演示**：戒指为 25 CPM、手机为 60 CPM，则每个字的输入时间分别为 2.4 秒与 1 秒。戒指若在准备／结束上净节省 5 秒，只有约 3 字及以内的任务可能更快；若净节省 10 秒，临界长度约 7 字。准备节省是否存在、具体多大，必须实测。

这个模型适合设计短搜索词、名称输入、短回复等任务，不能代替实验，也不能自动得出“戒指比手机高效”。任务较长时，较快的手机输入速度会逐渐占优。

## 8. 精读顺序与本轮结论

1. Ruan 等 2017，第 3.6.1 节及平行语料：明确中英文计量依据。
2. ThumbText，第 5.3—5.4 节：与本项目触摸面最接近，且提供同硬件不同策略的比较范式。
3. TipText，User Study 3：指尖输入、候选、补全、错误率与学习过程。
4. DRG-Keyboard，第 7 节：双戒指、完整候选过程、组均值与单人上限的差别。
5. RingByte 与 RingGesture：避免遗漏较新、更快的戒指路线。
6. Text Entry Throughput 与 Multilingual Phrase Sampling：完善速度—准确率和材料设计。

本轮判断：**25 汉字／分钟是一个有研究价值的熟练使用信号。现阶段最稳妥的定位是可行性与有竞争力的潜力；最有希望建立的效率优势，是同硬件、同语言和同任务下的直接优势，而非依靠中英文换算宣布领先。**

## 9. 补充：联想选字占比较高时，如何重新判断贡献

### 9.1 分清两个机制

- **部分笔画后的候选提前选字**：该字已经输入笔画，只是没有写完全部笔顺。它属于编码消歧／提前完成，不应与完全依赖上下文的下一字预测混为一谈。
- **无笔画的下一字／词联想**：前文已经足以把目标放进候选，用户直接选择后续文字。这部分输出应单独记录。

两者都可计入完整系统速度，但不能据此说明完整手写一个字的速度。也不能用 `25 × (1 − 联想输出占比)` 估计关闭联想后的输入速度：关闭后动作数量、候选扫描、等待和纠错都会改变，必须另行实测。

### 9.2 使用成熟预测不等于没有研究贡献

联想引擎可以是各条件共享的基础组件。论文贡献可以来自戒指编码、动作识别、候选操作或输入与纠错的切换，只要直接比较能将增益归因到这些设计。若只是使用现成联想产生较高总速度，则不构成新的联想算法贡献。

例如 TipText 同时使用候选和补全，并单独报告约 14.91% 的自动补全比例；其主要研究是极小指尖输入面的布局、空间模型与交互设计。它提供的是“明确贡献与公共组件、分开解释结果”的例子，不能直接证明本项目的创新性。[TipText 原文，Auto-Complete Rate 与 Conclusion](https://hongbofu.people.ust.hk/doc/TipText_UIST19_Final.pdf)

### 9.3 最小归因实验

| 条件 | 输入策略 | 上下文联想 |
| --- | --- | --- |
| A | 本系统笔画手势 | 开启 |
| B | 同戒指分区笔画选键 | 相同引擎与设置开启 |
| C | 本系统笔画手势 | 关闭无笔画的下一字／词预测，保留笔画匹配候选 |
| D | 同戒指分区笔画选键 | 同 C |

同等训练和中文材料下，A 与 B 的比较检验“在常规联想支持下，本系统交互是否有额外收益”；C 与 D 检验少预测支持时的策略差异。A 与 C 说明联想对本系统的作用，但不能单独证明本系统优于其他策略。四条件交互可用于考察不同策略是否从联想获得不同收益，不能仅凭某个条件数值较高就声称存在协同。

记录至少包括：有笔画输入后的提交字数、无笔画联想提交字数、每字笔画数、候选排名、选择／翻页耗时、纠错耗时、总任务时间和错误率。只记录联想字数不足以解释时间收益。

### 9.4 可以选择的研究主线与停止条件

1. **极小输入面上的中文编码与动作设计**：若共用预测后，笔画手势仍比选键更快、更稳或更易学，可将其作为核心贡献。
2. **笔画、候选与纠错的操作衔接**：若整体时间主要消耗于候选操作，且有明确的新交互设计，转向研究如何减少操作和模式切换成本。须与合理的常规候选操作比较，不能只把候选界面存在本身视为创新。
3. **学习成本与可迁移性**：若绝对速度优势有限，可研究熟悉中文笔形是否帮助新用户较快掌握戒指输入，以及跨天保持；这需要新手与纵向证据，单个熟练用户无法回答。

如果 A 与 B 差别很小，笔画／选字操作又没有独立、可验证的新设计，那么以“高效率”为主线的论证会偏弱。此时应重新定义实际未解决的问题，或做针对性的交互改进，而不是仅调整标题或把成熟联想包装为创新。
