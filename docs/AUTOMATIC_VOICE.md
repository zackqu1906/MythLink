# 自动识别：一次联合分类与提示词组合

自动处理、原有手势明确操作和共用能力的文件索引见 [语音代码分区](VOICE_CODE_MAP.md)。

设置 → 麦克风与语音 → 输入与控制 → 语音处理模式，选择“自动判断”。
沿用 `input/routingMode=auto`，在下一句开始时固定该句模式。手动转换保留原来的处理流程。

## 入口与处理顺序

1. 开始录音时固定输入目标，异步采集目标窗口的只读 OCR 上文。
2. 用户配置的**结束语音动作**结束本句，等待最终 ASR。默认 tap；自动模式下原“转换为编辑”动作也统一为结束，不预选听写或编辑，不改保存的手势绑定。
3. 最终 ASR、可编辑原文片段、只读 OCR 一起进入一次 Clef 请求，同时得到总体意图和本次可用任务。有原文时六个任务；原文为空或仅空白时，从请求中移除修改，剩五个任务。
4. 先校验接口概率格式，再应用听写优先策略：总体听写时始终进入听写；总体或任务概率并列、编辑但没有任务时回退听写。原始选择与概率保留，冲突／回退记录标黄。
5. 听写使用整理提示词及“只输出本次口述正文”的来源约束；编辑组合“通用约束 + 通用组合说明 + 命中任务规则 + OCR 边界”，一次性生成。
6. 释字拼写、直接重述统一属于修改，其规则随该模块带入，不再预测 hint。
7. 编辑用 `submit_text_edit.modified_text` 返回完整可编辑原文；没有逐模块生成、候选竞速或自动重试。
8. 原生输入法仍校验会话、版本、原文范围和目标后应用结果并保留撤销。选区优先；无选区只编辑光标前。

此变更不增加应用或场景提示词。自动模式没有手动转换或下滑润色入口；取消、撤销、发送仍复用既有能力，切回手动模式恢复原来的手势用途。这份分类与组合提示词只用于自动路径。

## 分发版连接与浮窗（0.6.8）

在设置的服务设置中填写“自动路由服务器”：SSH 域名/IP、端口、用户名、私钥路径，服务器内服务端口默认 30000。点击“保存并测试”会检查 SSH、Clef 健康接口和一次合成分类。配置保存在当前用户的 QSettings `clef/ssh/*`，只保存私钥路径，不复制或打包私钥。

应用使用 macOS 自带 `/usr/bin/ssh`，建立仅监听本机回环的随机端口隧道，Finder 启动也可用。首次连接记住主机身份，身份改变时拒绝连接；不转发 SSH agent。加密私钥需已经解锁到 macOS 钥匙串/ssh-agent。退出关闭隧道，SSH 进程断开后下次请求重建。服务器应已部署并运行 Clef；客户端不安装 Python/NPU 依赖，也不替换服务器进程。ASR 与正文生成仍需各自的服务配置。

浮窗：请说话 → 正在识别 → 正在判断 → 正在修改/插入/润色等 → 正在编辑（保留任务名）/正在听写 → 正在写入 → 已编辑/已听写。文字完整显示，按实际宽度扩展，自动模式以约 0.2 秒从当前宽度平滑伸缩；遵循 macOS 减少动态效果。自动模式只显示结束和取消/撤销，不显示右滑修改或下滑润色。路由失败时保留原始听写并明确提示失败。

原生 `automatic_routing_version=3` 包含上述状态协议；旧输入法组件会提示更新，不能静默缺失状态。进度消息复用 epoch/client/utterance/sequence 校验，仅改变显示，不改变编辑范围、revision 或写入权限。

真实 SSH + Clef + 火山 DeepSeek 的八类合成链路记录见 [连接链路报告](reports/automatic-ssh-pipeline-2026-11-05.html)。此验证不等同于第二台 Mac 的物理 Ring、麦克风或各外部应用写入验收。

## 六类任务边界

| ID | 任务 | 判断特征 | 排除边界 |
|---|---|---|---|
| `modify` | 修改 | 必须有可编辑原文；提供正确字词或整句来替换原文，指定删除对象；也包括日期、数量、量词、姓名的重述纠错和释字释词 | 没有可编辑原文时一律跳过修改；仅转述要求／姓名解释、照录不算修改；“改成更正式”属于润色；重排、翻译自然产生的变化不额外算修改 |
| `insert` | 插入 | 口述已给出具体原话，原封不动插入指定位置，可从空白开始 | 只给补充主题而需模型撰写，是润色；替换旧内容是修改 |
| `polish` | 润色 | 基于原文按语气、风格、想法调整，包含扩写、缩写、精简、摘要 | 用户已给出新增／替换原话时选插入／修改；授权重新构思主体的新稿是创作 |
| `format` | 格式整理 | 保留信息，仅重排、分段、列表、表格或排版 | 另外要求摘要时组合润色；移动位置很精确也不额外算修改 |
| `translate` | 翻译 | 将已有内容转换为目标语言 | 拼写更正是修改；新写外语稿件是创作 |
| `compose` | 按目标创作 | 模型按目标组织主体内容，允许大幅重写及增加内容，旧文可仅作素材 | 给出完整替换句子是修改；沿着原文扩缩写或改语气是润色 |

旧分类迁移到新分类：精确修改 → 修改；插入指定内容 → 插入；补充扩写和原内容整理中的精简／摘要 → 润色；原内容整理中的结构／排版 → 格式整理；翻译和按目标创作保留。旧内容整理样例已逐条按口述重新标注，没有把一个旧概率拆成两个新概率。

释字、偏旁、同音消歧、字母数字拼读及直接重述均包含在 `modify` 中，不再输出独立 hint。
“整句改成：周六下午在北门集合。”是修改；“改成更正式”是润色；“以这些材料重新写一篇”是创作。
“补一句原话：路上注意安全”是插入；“把原因补充详细”需要模型组织句子，属于润色。
“只改成列表”是格式整理；“精简成两条要点”同时要求摘要和列表，是润色＋格式整理。
特征是语义判断依据，不以出现“改成”“补充”等关键词强制路由。转述、个人计划和照录中的操作词仍按外层用途判断。
修改的 `skip` 选项明确排除转述姓名解释：即使原文恰有相似姓名也不能据此执行纠错。转述后另外委托系统执行，以及直接纠正本人已有输入，仍可选择修改。存在可编辑原文是修改的必要条件；原文为空或仅空白时，程序从请求 schema 移除 `modify`，口述和 OCR 中即使包含文字也不会恢复它。此规则只约束修改，空原文仍可选择插入或创作。未请求的修改显示为“不可用”，没有模型选择或概率，不伪造 skip 或 0%/100%。
旧 `precise_edit`、`verbatim_insert`、`expand`、`organize` 只用于历史展示；当前编辑计划不接受这些旧字段。

同一个独立需求尽量只归一个任务，不把完成该需求必然用到的操作重复计数。
多需求可以组合，例如“把伟改成王字旁的玮，再客气一点”选择修改和润色。
“写封客气的英文邮件，分三点”只选择创作，语言、语气和格式作为该创作的约束。
这些是分类提示词的语义边界，不是 Python 关键词覆盖规则，是否正确识别仍需实际模型评测。

不按 ASR 逗号拆成孤立片段。联合分类与生成阶段都保留完整口述，并要理解指代、补充解释和后续撤销。
组合模块的固定排列只保证可复现，不代表执行顺序；具体顺序及每项范围由文本模型结合完整口述确定。
分类计划只是提示，不能授权超出用户要求的改动。

2026-11-06 起，自动流程只在路由前按原文是否为空决定可用分类；空原文继续排除 `modify`。
路由完成后，正文生成和原生自动编辑不再按类别重复检查原文非空，也不再传递
`automatic_allow_empty` 许可字段。空字符串和空白原文原样传给正文模型，OCR 不代替原文。
仍保留请求长度上限，以及输入框身份、光标、组合文本范围和写回内容的一致性校验。
IMK 报告长度为 0、光标位于起点且没有读到非空上下文时，记录为可用的空原文；
空范围查询返回 `nil` 不再阻断该场景。非空读取结果优先，未知长度或矛盾坐标不伪装成空原文。
手动编辑的原文要求保持不变。

## 后续编辑生成提示词

设置的“输入与控制”中提供“自动模式听写整理”开关，默认开启，并保存到
`input/automaticDictationCleanupEnabled`。关闭时仍执行 Clef 联合分类；如果结果为听写，
直接将本次 ASR 文本交给原有注入流程，不创建正文模型请求。编辑结果继续走原来的组合生成。
每句提交路由时固定该开关值，切换不改变已经在处理的句子。历史记录保存
`mode.dictation_cleanup_enabled`，关闭时明确标注“直接使用 ASR 文本；未调用正文模型”，
保留当次路由 OCR；不虚构正文模型输入或 OCR 请求。手动模式沿用原有设置。

分类继续使用 v19 联合结构，当前路由提示词为 v20：修改按可确定的替换内容及与原文的对应关系判断，

`src/proximic_ring/text_processing/automatic_prompts.py`，不改手动手势的生成提示词。

没有明确顺序时由模型按实际对象和目标推断依赖，不预设任何类别优先级。
新增细分类只需补充该类执行模块，组合提示词不随类别数增加；单类也可能有多步，因此同样携带通用组合说明。

## 分类提示词的职责

三种内容统一在 `src/proximic_ring/text_processing/router_prompts.py` 维护：

| 内容 | 常量 | 负责说明 |
|---|---|---|
| 任务定义 | `EDIT_TASK_DESCRIPTIONS` | 本类处理什么对象、实现什么目的；保持简短 |
| 选项判据 | `EDIT_TASK_CRITERIA` | `apply` 的正向证据和 `skip` 的排除条件，重点覆盖转述／照录、相邻类别和组合任务的易错边界 |
| 联合规则 | `JOINT_ROUTING_RULES` | 总体与任务的预期一致性、多项独立需求的组合、自然产生的字词变化不重复计数、创作内部约束 |

判据不能只有反例：没有正向的 `apply` 条件，模型仍不知道什么情况下应选中本类。
不在三处逐段重复类别说明，也不以完全零重复为目标；判断当前口述是否实际委托该任务，是每个选项的必要前提。
共同的听写／编辑边界仍由 `CLEF_ROUTING_PROMPT` 和 `CLEF_ROUTING_CRITERIA` 维护。
描述放在各题的 `instructions`，选项判据放在 `criteria`；共享 `state` 保留共同意图边界、联合规则和实际输入，不再复制完整六类定义。
这些 Python 常量是项目组织方式，`description` 不是额外的接口字段；仍然是一次请求。有原文时七道 choice 题，无原文时六道。
听写优先、无明确任务回退和冲突标黄仍由后置校验负责。提示词重排可能改变模型分数，必须以真实服务回归验证。

## Clef 接口

使用服务器 Jev/SystemOne 兼容的 `POST /v1/systemone`，不启动本地 GLiNER，不使用聊天补全接口做分类。

- 每句仅一个请求：`questions.voice_intent = choice(dictation, edit)`，另有最多六个 `choice(apply, skip)` 任务。`routing_schema(target=...)` 在原文为空或仅空白时移除 `modify`；真实输入文字“空”属于非空原文。
- 听写也返回所有已请求任务的全部概率；每题内概率和约为 1，不同任务可以组合。被禁用的修改不请求、不返回、不计为模型 skip。
- `joint_router_input()` 把共同边界、联合规则和实际输入放在共享 `state` 中；`routing_schema()` 在各题内提供任务定义及判据。服务器 `systemone()` 对一个 record 调用一次模型；这不代表七个预测必然一致。
- `resolve_joint_decision()` 使用 `dictation-priority-v1`：总体听写优先于任务 apply；概率并列或编辑全 skip 回退听写。实际听写不携带编辑计划，原始 apply 保存在 `raw_tasks`，被忽略项写入 `ignored_tasks`，以 `warning_codes` 和黄色提示记录，不作为调用失败。
- 响应字段必须与本次动态 schema 完全一致；缺项、多项（包括空原文时返回 modify）、非数字、布尔、非有限值、超范围、概率和异常及 choice 不符最大概率均拒绝。计划校验再次检查原文对应的可用任务集合。
- 官方响应保留四位小数，容许每项 0.00005 的舍入误差。
- 不重试、不跟随重定向；请求前后检查取消，丢弃已取消的结果。超时只覆盖一次分类请求。

服务启动后，在**主程序进程启动前**设置：

```sh
# 示例为本地转发地址，并非已部署地址。
export PROXIMIC_CLEF_URL='http://127.0.0.1:30000/v1/systemone'
export PROXIMIC_CLEF_MODEL='clef-flash'
export PROXIMIC_CLEF_TIMEOUT_S='15'
# 如服务需要鉴权，通过 PROXIMIC_CLEF_API_KEY 设置 Bearer token。
.runtime/venv/bin/mythlink-ui
```

地址必须完整填写；没有默认公共服务。鉴权独立于文本模型的 API Key，不写入分类 trace。
主程序启动时只校验配置，不发送用户内容、下载权重或负责服务器预热。
终端 export 不影响已运行或从 Finder 启动的应用。

原生输入法需要一并重建更新：新协议为 `automatic_routing_version=2`，只接收听写／编辑和显式的空原文许可。
旧四分类输入法会在会话开始时被拒绝，并提示更新组件，避免把编辑指令误当正文。
只有纯插入指定内容或创作计划允许空原文；混合计划含任何需要已有原文的任务仍要求有效原文。

## 记录与错误处理

历史记录保存本次实际联合 schema、共享边界规则、版本、模型、已请求问题的完整概率、分阶段及总耗时、编辑计划和实际组合提示词。trace 的 `request_schema` 保存实际请求；`task_availability` 使用 `modify-requires-source-v1`，记录可用任务及因 `no_editable_source` 排除的修改。后置听写优先策略仍为 `dictation-priority-v1`。
历史列表默认维持简略显示。在一条语音记录的“更多 → 查看记录详情”展开区，
点击“查看自动识别完整记录”才加载总体意图、编辑任务、概率、耗时、截图和模型输入。
完整记录上下都有关闭入口，关闭后恢复简略详情；收起整条记录或切换记录也会重置展开状态。
正常听写显示可用任务跳过；空原文的修改单列“不可用（无可编辑原文，未参与分类，无模型概率）”，不因类别禁用本身标黄。听写优先或不明确回退时显示最终听写、被忽略的编辑任务和原始分数。历史列表整条标黄，详情保留黄色原因说明，不把原始 apply 改成 skip。旧两级记录及旧严格校验失败继续按当时结果展示。

自动模式取得的当次目标窗口截图随该条记录本地保存为 `screen-<capture_id>.png`，详情可预览、打开原图，
并以橙框显示 OCR 区域。`record.json` 的 `screen_evidence` 保存截图时间、尺寸、原始 OCR 行的文字、
坐标、置信度及规则处理标记；`passed_filter` 只表示通过行过滤，之后仍受合并和长度上限限制。
`mode.screen_context` 是过滤后的上文，`mode.router_trace.input_state` 是分类器的共享输入，
`llm.requests` 保存实际组合提示词及准备的文本请求内容。保存请求不代表模型一定成功返回，也无法证明模型实际依赖了哪句上文。
2026-11-06 起，完整记录分别展示“Clef 路由 OCR”和“听写整理 OCR／编辑生成 OCR”：
`mode.router_ocr_text`（同时保存在 `router_trace.ocr_text`）是本次分类输入中的精确片段，
只取最后 4 块拼接后的末 360 字符；`llm.requests[].request_input.screen_context` 是正文处理时，
在 OCR 解析及输入校验之后，从序列化请求正文保存的完整只读上下文，不再按路由规则裁剪。
两个字段各自保留快照，不因后续 OCR 对象变化而改写；正文结果返回时也更新原有 `input` 和 `screen_context`。
请求仍在排队、没有进入正文处理、生成前校验拦截、网络失败会分别说明；请求失败不等于服务器收到。
旧记录沿用当时保存的输入，没有独立保存的路由片段显示“未记录”，不按当前规则重新生成历史证据。
图片和原始 OCR 诊断信息不进入模型输入；截图编码或存储失败会记录原因，不阻断文本处理。
删除该条历史会一并删除截图，旧记录不会补拍当前窗口来冒充当时截图。

网络或无效响应导致的分类失败沿用原来的保留本句听写流程并显示／记录错误，不改原文、不静默切换旧模型。
分类成功后如果缺少必要原文、生成失败或原生原文校验失败，不把不完整编辑结果写回。
取消、应用切换、过期会话及重复最终 ASR 继续受已有会话和请求校验约束。

- `src/proximic_ring/text_processing/router_prompts.py`：联合 schema、共同意图与任务边界。
- `task_routing.py`：总体意图、编辑计划、一致性与概率校验、原文要求。
- `intent_router.py`：单次 HTTP 请求、响应校验、取消和 trace。
- `automatic_prompts.py`：自动路径专用的组合提示词。
- `automatic_processing.py`：自动路径的一次整体生成；`llm.py` 提供共用请求与结果校验，`worker.py` 分派执行。
