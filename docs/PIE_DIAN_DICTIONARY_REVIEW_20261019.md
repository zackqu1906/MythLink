# 撇点统一保留一笔／两笔解释的字典检查

## 结论

常用字范围内，统一保留单笔`z`与双笔`pn`解释会增加早期候选，后续笔画大多能消歧；没有观察到完整常用字的大面积新增重码。主要风险是排名：刚写一笔撇点时，双笔解释会额外带入“人、入、八、乂”等已完成字。如果把两种解释等权，并沿用完全匹配优先的规则，它们可能挤进前排。因此可以把双解释作为统一的底层能力，但应加入拆笔代价、形状门槛、每字拆分次数上限，再验证实际前五候选。

本次只做离线统计，没有启用主程序拆笔或改变候选排序。

## 数据及方法

- 实际运行字典`src/proximic_ring/assets/strokes.json.gz`：102,597个不同字符、186,955条笔序记录。
- 同时统计6500常用字表和全字典两个候选范围，不把全字典假定为6500字。
- 本地缓存`cnchar-order`3.2.6用于区分真正的撇点与其他折笔。它覆盖6366个常用字，其中223字含明确的撇点；这223字的规范五类笔序均存在于实际字典。
- 对这223字的真实撇点位置提供`z/pn`两种解释，其他笔画假定识别正确。连续多个撇点的全部分支都保留。全字典实验仍使用这223个常用目标字，只扩大候选池。
- 每条解释匹配当前字典的全部合法笔顺，按字符去重。统计的是显示截断前的候选池，不是屏幕同时显示的字数。
- “前缀匹配”包含尚未写完的较长字；“完全匹配”要求候选的完整笔序已输入完。二者分开统计。未加入模糊替换、前文语言模型、拆笔惩罚或轨迹阈值，因此结果不能当作实际前五候选准确率或运行性能测量。

## 具体结果

下表均为6500常用字范围。女、如、好、安都按正常单笔撇点输入，双笔分支只是额外后备。

|已写到的位置|只按一笔解释|同时允许一笔／两笔|新增|
|---|---:|---:|---:|
|首笔撇点|723|890|167|
|女：再写第二笔撇|243|272|29|
|女：三笔写完|114|121|7|
|如：全部写完|16|16|0|
|好：全部写完，子采用zsh版本|5|5|0|
|安：全部写完|2|5|3|

“女”写完新增的是乎、释、翻、番、悉、釉、鄱，均只匹配到它们的前缀；没有新字与女完整重码。“安”新增窄、窑、窖，也都未写完。

223个目标字去重后为221种完整物理输入序列：217种的候选池完全不增加（98.2%），只有女、安、汝、桉对应的4种序列增加前缀候选；**221种序列都没有新增常用字完全匹配**。这不表示候选第一名或前五绝不变化：早期输入、笔画识别误差及模糊替换不在这个结论内。

在全字典范围，首笔候选从10,296增到15,307（新增5,011）；完整输入时221种序列中的201种不增加候选，3种出现新增完整重码，新增字分别为“巡→𬨟”“甾→畓”“案→𫁍”。生僻字扩大了噪声。

## 衣字旁

物理输入为点、折、竖、一个撇点形轨迹时，对应`nzsz`或`nzspn`：

- 常用字候选：单笔分支15字，双笔分支49字，去重合计64字。
- 全字典候选：单笔分支88字，双笔分支871字，去重合计959字。
- 常用范围内继续写“初”的刀后，剩3个前缀候选（被、初、褶），只有初完全匹配。
- 继续写“补”的右部后，剩3个前缀候选（补、裆、裥），只有补完全匹配。
- 继续把“被”写完，只剩被。

这49个常用候选大部分正是希望恢复的衣字旁字，不能全算作新增噪声。相对于“正确分成两笔”的49字，保留原单笔解释多带入的是另外15字，而非多出49字。

## 连续多次歧义与建议

223个目标中，207个有1个撇点，1个有2个，15个有3个。三个撇点同时提供双解释，最多产生8条编码路径，例如巢开头的三个撇点：常用候选由9增到23。如果限制每字最多拆一次，最多4条路径，候选降为19。次数上限能减少分支，但单独使用仍不能防止早期的完整短字抢位。

建议离线首版采用：

1. 轨迹对撇点有足够支持时才生成`pn`后备，正常`z`解释始终保留，不对所有折笔开放。
2. 双笔解释增加代价，在字内衤对应位置或后续笔画支持时提高其竞争力；不要因分成两笔后碰巧形成完整短字就无条件排前。
3. 首版每字最多使用一次撇点拆分；候选按字符取最佳路径去重，保留现有显示数量。
4. 保留当前衤、小幅正常撇点采集任务。用真实样本测量正常单笔误拆及前五候选变化，再决定是否扩大默认启用位置。
