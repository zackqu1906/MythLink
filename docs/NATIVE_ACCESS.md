# 辅助功能授权后的实时恢复

`CGPreflightPostEventAccess()` 在某些 macOS 场景中会在进程内保留旧结果。
仅定时重复调用这个函数不能解决授权后仍返回 false 的问题。
相关讨论：https://developer.apple.com/forums/thread/727984 。

## 实现

- UI/ASR 主程序持有 `NativeAccessChannel`，通过继承的标准输入输出管道通信。
- 安装版调用自己的可执行文件加 `--native-access-worker`；源码调用同一解释器的模块入口。
- 工作进程负责实际 Accessibility 元数据读取和原生按键发送，自己检查两项权限。
- 返回未授权后结束工作进程。下一次后台检查或用户操作使用新进程，不沿用其拒绝缓存。
- 权限就绪时复用工作进程，避免每次快捷键都启动新进程。未授权每秒检测、已授权每十秒检测。
- 不改变系统授权、签名或输入源。旧签名/副本授权不匹配时仍需用户为当前 App 授权。
- 授权变化不重启 UI/ASR，不自动执行之前失败的编辑、删除或发送。

所有按键固定目标进程。应用快捷键的 AX 对象保留在工作进程，只向主程序返回随机句柄；
工作进程更换后，旧句柄拒绝执行。回复丢失、超时或中断时不重试，以免重复发送。
普通句子删除/光标指令同时检查请求前和工作进程执行时的目标 PID。

## 验证边界

`tests/test_native_access.py` 用真实子进程模拟“启动时缓存拒绝、后续授权不刷新”，验证主进程
PID 不变，拒绝后工作进程更换，授权后操作成功，以及拒绝恢复不会自动重放旧操作。
另有真实源码工作进程的只读权限 API 冒烟检查、打包入口、断线不重发、目标句柄失效测试。
这些回归不等同于实际 macOS 设置开关的端到端验证。

实际安装版验收：保持主程序打开，在系统设置给当前 App 开启辅助功能；等待权限提示恢复，
然后触发新的编辑/撤销/应用手势，检查成功且主程序 PID 未变。日志的 `pid` 是主进程，
`control_pid` 是执行按键的工作进程，`control_channel=worker` 表示使用新通道。
DMG 不在此次构建范围，测试更新使用 `scripts/build-macos.sh --app-only`。

2026-09-21 本机源码通道只读测量：首次启动约 200 ms；就绪后连续 30 次权限查询中位数
11.69 ms、最大 15.23 ms，复用同一工作进程。此测量未发送按键，不是端到端手势延迟。

2026-09-21 安装版实际授权测试：10:30:26 未授权，10:30:48 两项权限均为 true；
主程序 PID 保持 11063，工作进程从 11085 换为 11200。已验证系统开关授权后
主程序无需重启即可得到可用权限；实际编辑/撤销操作仍等待用户确认。
