# 点击被识别为笔画：测试与解决步骤

适用入口：ProximicVoice 主程序笔画页及 `tools/collect_stroke_samples.py` 测试窗口。
日期：2026-10-07。本文是基于代码和已有日志的排查结果及实施方案，未宣称已完成实机修复。

## 1. 已核实的行为

- `StrokeCollector` 按 SDK 确认的接触边界收集轨迹；累计路径至少 1.5 个处理后位移单位且至少 5 点，就可送入笔画识别。
- `ClickDetector` 在 200 Hz 帧序上要求接触持续 `0 < end-start < 40`，即严格小于 200 ms；接触内原始速度积分的净位移不得超过 0.02。它与处理后像素轨迹使用的量不同，不能直接比较阈值。
- `TouchpadStrokeOutput` 对短轨迹等待 30 ms 或后续 3 帧，让 SDK `TouchpadClick` 优先。现有测试覆盖了同批次接触、移动和 SDK 点击仲裁；它们均通过。
- 主程序固件手势 `class_id=5` 走另一条回调，只执行候选确认。测试窗口也直接确认候选。这条回调没有取消对应接触的待提交笔画。
- 开启固件手势时忽略 SDK 点击确认，是为避免重复确认；这并不等于排除了固件点击产生的笔画轨迹。
- DTW/结构识别只在有效笔画轨迹内选择类别，不能通过换模板来可靠解决点击与笔画的分流。

因此首选调查方向是两路事件的动作归属与仲裁；30 ms 等待的跨批次风险也需要回放验证，尚不能单独认定为实机根因。

## 2. 已完成的基线检查

运行以下命令，临时测试数据保存到项目内，避免系统临时目录权限影响结果：

```powershell
.runtime\venv\Scripts\python.exe -m pytest tests/test_stroke_input.py tests/test_stroke_contact_test.py tests/test_touchpad_sdk.py --basetemp data/stroke-test/tap-baseline-tests --tb=short
```

结果：40 项通过。覆盖 SDK 原始点击规则保持一致、接触边界、抬手裁剪、缺帧重置、增益后的点击优先以及短笔画保留。
现有测试没有覆盖固件点击与同一接触轨迹的交叉仲裁，因此通过基线不代表这个问题不存在。

另有两项界面基线通过：固件手势选字/点击确认、真实笔画工作线程向 QML 传递轨迹。
Windows 默认控件样式会使界面测试在清理阶段因既有的自定义样式警告报错；使用项目可自定义的 Basic 样式复跑后两项通过，无需修改产品代码：

```powershell
$env:QT_QUICK_CONTROLS_STYLE='Basic'
.runtime\venv\Scripts\python.exe -m pytest tests/test_ui_touchpad.py -k 'compact_stroke_page_ring_gestures_and_tap_commit or real_stroke_worker_delivers_numeric_trace_to_qml' --basetemp data/stroke-test/tap-ui-basic-tests --tb=short
```

已有实机日志 `data/stroke-test/20261005_012220_881195.jsonl` 中有 182 次笔画输出、10 次固件点击和 6 次 SDK 点击。
两次固件点击附近出现了笔画输出：

|固件点击时间（日志本地时间）|笔画相对点击的输出时间|输出|点数|
|---|---:|---|---:|
|2026-10-05 01:24:08.869536|+34.86 ms|h／提|26|
|2026-10-05 01:25:32.998860|-30.93 ms|h／提|13|

这些是排查线索，不能直接算作两次误识别：旧日志没有动作意图标签，也可能包含相邻的两次真实动作。
日志时间还是 UI 收到事件的时间，不能直接用来设置生产仲裁窗口。两种点击数量也不能据此计算漏检率。

复算：

```powershell
.runtime\venv\Scripts\python.exe tools/diagnose_stroke_taps.py data/stroke-test/20261005_012220_881195.jsonl --output data/stroke-test/tap-diagnosis-baseline.json
```

工具默认的 250 ms 只用于寻找人工复核线索，不是修复阈值。

## 3. 补齐观测信息

在两个入口使用同一份诊断事件结构，并在输入链路记录，避免只记 UI 最终结果：

- 会话编号、接触编号、人工任务标签（点击、笔形、组合任务），点击是否用于确认候选。
- 接触开始/结束帧、确认帧、设备 uptime、主机单调接收时间与队列处理时间。
- 增益前速度、增益后位移、累计路径、净位移、包序号、缺帧和重置。
- SDK 最终点击判定及理由：通过、时长超限、位移超限或帧缺失。
- 固件点击序号、`center_uptime_ms`、收到时间；不能只记 `class_id`。
- 最终动作决定：确认一次、提交笔画、忽略，以及采用哪个证据、耗时多少。

当前测试日志没有增益前速度或 SDK 拒绝点击的原因，不能从旧日志反推这些值。
固件中心时间与触控帧须先建立同一会话的时间映射，处理设备重启及 uint32 回绕，不能假设两种编号直接相等。

## 4. 采集带意图标签的对照样本

断开主程序戒指连接后运行测试窗口，确认佩戴方向。先记录当前版本、固件、模型及增益配置；测试中保持一致。
采用独立诊断计划，不把点击混入现有笔画训练模板。

第一轮建议 150 次有效任务：

|任务|数量|目的|
|---|---:|---|
|轻点、正常点击、偏慢点击|各 20，共 60|观察时长、抬手及位移差异|
|短点、短横、短竖|各 20，共 60|保护最容易被点击门槛吞掉的真笔画|
|写一笔后立即点击确认|15|区分相邻动作与一次动作的双输出|
|点击后立即写下一笔|15|防止仲裁误吞下一笔|

逐次预先显示任务；实际没有按任务执行的样本标为模糊，不强行当作点击或笔画。
先查固件手势开启时的主路径；对疑似重叠样本再在关闭固件手势的模式做对照，不混合统计两种模式。
重新佩戴后再采独立验收轮，不能用同一批数据同时调参数和声称验证成功。

## 5. 按证据定位问题

|观察到的现象|优先处理方向|
|---|---|
|同一接触有固件点击，但 SDK 没有点击，仍输出笔画|补齐固件点击与触控轨迹的统一仲裁|
|同一接触有 SDK 点击，仍先输出笔画|修正跨批次事件关联及提交时机|
|人工点击，两路都没判点击|用时长、原始净位移、累计抖动等特征检查点击检测边界|
|一个动作出现两组接触或缺帧|先处理接触边界或数据完整性|
|真实短笔画被判点击|检查 SDK 点击规则是否与笔画输入任务冲突|

只有带标签并成功关联到接触的记录，才进入误识别统计。

## 6. 首选实施方案：识别前统一仲裁

在 `TouchpadStrokeOutput` 前后设置共享动作仲裁层，主程序和测试窗口均复用；固件确认不要绕过它直接执行。

流程：接触收集 → 完成轨迹暂存 → 关联 SDK/固件判定 → 只提交一次最终动作 → 真笔画进入 DTW。

- 使用接触 ID 及统一时间信息关联证据。固件点击只消费其匹配接触，避免用“点击前后全部丢弃”的全局冷却规则。
- SDK 已明确确认点击时，匹配接触不进入 DTW。固件开启时由固件拥有候选确认；关闭或不可用时保留 SDK 确认回退。
- 固件点击先到：保存匹配证据，后到的同接触轨迹不得提交。轨迹先到：暂存到仲裁完成后再决定，避免笔画污染候选后再确认。
- 为 SDK 输出显式的接触最终判定，区分“不是点击”与“还没收到点击结果”，减少依赖猜测性的 30 ms 等待。
- 固件关联的等待上限根据新日志中的设备时间与接收延迟分布确定，并与下一动作隔离；超时仍须有明确的笔画/忽略决定，不能无限等待。
- 清除、停止、断开、过期事件、队列溢出和设备重启时清空待处理动作及确认标记。
- 每个接触最终动作最多一次。同一固件事件序号去重；不能让一个点击既新增笔画又确认候选。

若人工点击没有任何点击判定，另行在增益前添加任务专用的点击/笔画判别。先比较两类特征分布，再固定规则或小模型；无法区分的接触可忽略重试，但不要把所有短轨迹都判为点击。
不要凭 1.5、0.02 等现有数字直接抬高门槛，也不要仅增加 DTW 模板。控制层阈值与原 SDK 鼠标行为应分离，避免牵连鼠标模式。

## 7. 先复现失败，再验证修复

补入能在旧版失败、修复后通过的回归用例：

1. 固件点击先到、轨迹后到，最终只确认一次。
2. 轨迹先到、固件点击后到，最终无额外笔画。
3. SDK 点击与接触跨批次交付，以及移动增益放大时的点击。
4. SDK 和固件同时报告一次点击，确认不重复。
5. 真正短点、短横、短竖没有匹配点击时保留。
6. 连续点击、写后点击、点击后写：按接触关联，不串到下一笔。
7. 固件通道不可用时的 SDK 回退；重连、缺帧、队列溢出和停止时丢弃未完成动作。
8. 主程序与测试窗口回放同一事件序列，最终动作一致；候选确认采用未被伪笔画污染的笔序。

回放必须保留采集到的事件批次、顺序和延迟，再增加受控延迟变体；不能把全部事件排序后一次喂入来掩盖时序问题。
重新跑现有 40 项基线，以及 `tests/test_ui_touchpad.py` 的笔画/手势用例和鼠标模式回归。

## 8. 独立实机验收与交付

再次佩戴并独立执行同样的 150 次任务，主程序和测试窗口均验收。建议预先约定：

- 60 次人工点击中新增笔画为 0，重复确认为 0；确认成功率单独报告，避免用忽略所有点击达到零误输入。
- 60 次真实短笔画至少保留 57 次，且不低于旧版同任务对照；这里衡量动作分流，五类识别准确率另报。
- 30 次相邻组合动作不吞真实笔画、不污染候选、不重复确认。
- 报告端到端新增等待的中位数与 P95；开发前确定可接受延迟预算，再检验，不只报告 DTW 计算时间。

小样本零错误不代表长期零错误，需要注明次数、参与者及佩戴条件。
交付内容应包含：带标签事件日志、旧/新逐动作回放结果、最终参数及依据、回归测试结果、两入口实机验收结果和回退方式。
当前已完成代码排查、40 项核心基线及两项界面基线、旧日志线索提取及本方案；真实意图标签、统一仲裁实施和独立实机验收仍待完成。
