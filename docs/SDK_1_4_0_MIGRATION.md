# 主项目 SDK 1.4.0 更新记录（2026-09-28）

主项目已接入随附 Android public SDK 1.4.0 的 macOS 协议实现。源代码运行入口是项目根目录的 `启动行内听写.command`；`dist/Proximic Voice.app` 同步重建。

## 语音

- 界面、RecognitionRuntime、RingAudioSource、SDK MIC、命令行和数据采集默认 ADPCM。
- 自动将已保存的 PCM／Opus 界面选项迁移到 ADPCM。
- 戒指发送 IMA ADPCM，电脑解码为 16 kHz、单声道 PCM16，之后接入原有近点检测、ASR、输入法及文本处理流程。
- 校验数据头、分片数量、长度、乱序、重复、序号回绕及超时。组包只保留一个有界块；解码后立即写 WAV，不随录音时长积累完整音频块。
- 默认启动命令为 `20 00 01 80 80`，使用固件默认硬件／软件增益。明确指定增益时支持协议的 0.5 dB 步进。
- ADPCM 无需 libopus。SDK／CLI 保留显式旧编码诊断选项，供支持它们的旧固件使用；产品界面统一使用 ADPCM。

## 手势和其他协议

- 使用固件 START／STOP 与 `26 06`、`26 07` 确认事件，与语音共用 BLE 会话。
- `26 05` 中间分类结果不会驱动应用动作。置信度与时间戳来自固件，电脑不做二次分类或阈值判定。
- 分发线程使用有界队列，避免桌面动作阻塞蓝牙接收。静止期间没有手势事件属于正常状态。
- 保留 tap、snap、clench、上下左右滑、食指／中指捏合、顺逆时针画圈的既有动作名称和用户绑定。菜单、确认、撤销、转换、锁屏恢复等继续走原来的动作路由。
- 不再启动电脑端手势推理，也不为手势开启原始 IMU。可选的原始 IMU 数据采集独立保留，默认关闭。
- 新增 `RingSession.quaternion_on(on_frame=..., sample_rate_hz=200)` / `quaternion_off()`，支持 public 固件四元数；它和原始 IMU 采集互斥，与固件手势相互独立。电量、按钮和设备信息沿用 SDK。
- 本次配套固件是此前在 8F56 上独立验证过的 `1.2.133.public`。其他旧诊断命令是否支持取决于固件，不自动回退电脑端模型。

## 清理范围

已删除电脑端手势适配器、分类器、推理线程、密度模型、预处理、权重、参数、旧测试工具及对应文档；清理源码缓存和构建副本，重新生成 App／DMG。冻结程序的 Python 归档也检查了不存在旧手势模块。

近点检测、本地 ASR 和文本模型属于语音功能，继续保留；其 Torch 等依赖仍然需要。没有改写 Git 历史，也没有删除项目外其他 SDK 目录。
