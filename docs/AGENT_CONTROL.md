# Agent 能力选择与电脑控制释放

Agent 的会话提示词定位为通用助手，支持问答、解释、资料检索、写作、计算、代码、文件和应用操作。无需工具的任务直接回答；需要工具时按任务选择当前已提供的检索、连接器、API、文件、代码执行或 Computer Use。文件结果按内容/测试等合适证据验证，不再要求所有任务都打开应用、原生保存或截图核验。具体可用能力仍由 Codex 配置和当前工具提供。

登录和 App Server 连接仍必须有效。Computer Use 能力检查变为可选：缺少/未启用电脑操作工具时提示能力暂不可用，基础连接仍可用于其他任务；协议/传输异常仍按连接失败处理。重新检查连接可以更新能力状态。实际命令、文件、服务权限请求仍通过原有请求卡片处理。

2026-10-19 真实任务验证：计算 1～100 的平方和并写入 `calculation.txt`。Agent 使用一次 `commandExecution`，得到 `338350`，并完成公式和文件回读核验；没有模型发起的 Computer Use 调用。报告与独立经验记录位于 `.runtime/general-agent-checks/20261019-151349/`。回归覆盖缺少 Computer Use 时普通任务结束/队列推进，以及实际出现电脑操作后仍执行释放。

## 任务结束后的电脑控制释放

Computer Use 可用时，`turn/completed`（成功、失败或取消）沿用当前任务连接上的收尾，收到成功回执后才展示结束状态；正常完成才调度下一项任务：

1. `mcpServer/tool/call` 调用 `cua_repl.turn_ended`，绑定本次 `threadId/session_id` 和 `turn_id`，发送 `Stop` 生命周期事件。
2. 在同一线程调用 `cua_repl.js_reset`。仅结束浏览器生命周期不会关闭 macOS 原生 Sky 连接；重置此线程的运行时才能释放其原生连接。

重置不关闭原生应用或抹掉应用内容。模型对话和本客户端记录的应用授权保留。正常结束后运行下一条排队任务；失败或取消后，其余排队任务记录为取消，需要执行请重新提交。Agent 使用浏览器接口创建的结果标签页须按工具文档标记为 deliverable，让浏览器收尾保留结果；不会通过关闭 Chrome、结束共享 Computer Use 服务或撤销系统权限来释放控制。

下一次需要操作界面的任务须重新初始化 `cua_repl` 并观察当前应用，不再复用上一轮的 JavaScript 变量或控件引用。清理期间新输入留在客户端命令队列。重复／其他线程／旧任务的完成通知不会重置新任务。

如果已确认 Computer Use 不可用，且本轮未出现该服务的工具调用或授权请求，则跳过 Computer Use 收尾并记录 `computer_control_not_used`，普通任务可正常结束和继续排队任务。即使连接检查时不可用，只要本轮实际出现 Computer Use 调用，仍必须执行收尾；不因能力检查结果而漏掉释放。

两步分别最多等待 3 秒、重试一次；即使浏览器收尾失败，仍尝试关闭原生连接。未确认成功时记录 `computer_control_release_failed`，关闭本次 Agent 连接并阻止下一项任务启动，不显示“已释放”。电脑操作能力就绪仍要求工具提供 `turn_ended` 和 `js_reset`。退出连接时也按上述条件清理尚未结束的本次任务。

```sh

```

## 取消与动作组织

Agent 只提供取消，不再支持暂停 / 继续及输入时暂缓。取消先回复正在等待的请求，收到请求结束回执后发送 `turn/interrupt`；之后到达的工具请求仍被拒绝。重复点击不会重置这一等待顺序。正在启动的任务会在取得 turn ID 后中断。取消不撤销已发生的操作。

客户端不再要求每次 `cua_repl` 调用只包含一个 UI 动作和一次观察。Agent 根据实际状态组织操作，在需要重新定位或确认结果时读取观察；记录和 Workflow 提取保留完整调用、返回及已知观察，不补造批量调用的中间状态。

## Agent 浮窗与主界面的独立焦点

Agent 焦点只表示输入和手势当前属于 Agent 浮窗。将 Mythlink 从 Dock、应用切换器或主窗口入口带到前台，不会展开 Agent 或将输入转交给它；点击浮窗、Agent 入口或焦点切换手势才会进入 Agent。进入 Agent 不会显示、还原或抬高主窗口。

macOS 浮窗失焦后禁止自动接受焦点，并清除 AppKit 缓存的键盘窗口，保留浮窗、草稿和执行状态。输入法激活辅助窗口期间继续保留原输入客户端。请求卡片退场动画只在焦点仍属于该卡片时转回 Agent，避免用户已经点击主界面后又被抢回。

2026-10-20 补充修复：原先的输入法辅助工具只按应用 PID 返回前台，即使 Agent 已有键盘焦点，AppKit 仍可能抬高同进程的主窗口。现在 Agent 语音/笔画启动时绑定实际的 Qt 窗口；辅助工具完成输入上下文刷新后，通过 `restore_focus` 交接给宿主，仅恢复该窗口。辅助工具不再对 Agent 执行应用级返回。交接只允许原父进程，窗口关闭、失效或用户切到其他窗口时取消，不寻找或激活主窗口。外部应用保持原有输入法切换路径。

原生回归只使用临时窗口和测试文字，覆盖主窗口可见、最小化、隐藏时的独立焦点、直接点击和原生输入：

```sh
PYTHONPATH=src PROXIMIC_TEST_AGENT_NATIVE=1 .runtime/venv/bin/python -m pytest tests/test_agent_focus_native.py
```

`tests/test_agent_ime_focus_native.py` 另行编译使用真实焦点交接函数的临时辅助程序，执行实际 AppKit 来回切换，但不改变系统输入法。旧实现复现了主窗口被抬高；修复后后台、最小化、隐藏三种状态均保留，Agent 继续接收输入。Python 回归同时覆盖用户切换窗口、恢复失败与迟到结果不会继续启动本句。

## Companion 任务卡片

任务浮窗采用紧凑的深色圆角卡片、细边框和圆形状态图标。失焦时收为 344 × 84 的状态卡；进入输入时展开。空闲和任务结束后，展开与收起形态的左上角都显示关闭按钮。执行中保留取消任务入口；等待回答/授权、语音输入或截图尚未结束时不能关闭浮窗。

失焦形态的关闭、状态标记、任务切换、加号和链接统一为 24 × 24，放在同一行并垂直居中。关闭按钮仍直接隐藏当前卡片，不先激活浮窗；任务切换计数在固定按钮内居中显示。

关闭只隐藏浮窗，保留草稿、附件、对话和结果，不向任务发送取消、不打开主窗口；下次显式唤起继续使用。关闭时使旧焦点回调失效，防止迟到回调重新展开浮窗。

2026-10-21 关闭按钮补充：关闭前复用已有的原生浮窗焦点保护，先释放 Agent 的临时应用激活，再撤销卡片键盘焦点。关闭后的短暂激活尾部继续保护原窗口顺序，并跟随用户新选择的应用；用户主动点击主界面立即结束保护。多任务中点击未选中卡片的关闭按钮不会先激活它，关闭中的卡片也不再响应迟到的焦点进入事件。`tests/test_agent_dismissal_native.py` 用独立进程和真实按钮点击覆盖快速关闭、展开、收起、其他任务获得焦点以及主窗口后台、最小化、隐藏状态。

Dock/Finder 的原生 reopen 事件与菜单栏“显示主窗口”统一进入显式主窗口入口：先结束 Agent 的临时焦点保护、使旧焦点捕获和延迟返回失效，再还原并激活主窗口。应用级激活本身不作为打开主窗口的指令，以免语音输入或关闭浮窗时误唤起它。原 Qt 应用委托的其他生命周期和菜单回调继续转发；任务、草稿和附件保留。原生回归使用发送给测试进程自身的 reopen AppleEvent，覆盖 Agent 获得焦点、失焦保护期间、关闭保护期间的主窗口显示／最小化／隐藏状态。

原生焦点调用移植自 [Wails 的 NSPanel 实现](https://github.com/wailsapp/wails/pull/6008)，固定提交与 MIT 许可保留在 `mac_window_focus.py`。浮窗入口使用 `orderFrontRegardless` + `makeKeyWindow`；普通主窗口入口先显式激活应用，再 `makeKeyAndOrderFront` + `makeKeyWindow`，不依赖 Qt 的通用激活请求完成最小化后的键盘焦点恢复。当前语音／笔画输入仍要求宿主前台 PID，因此 Agent 取得 key 后保留独立的输入法宿主激活和窗口顺序保护；这部分是 Mythlink 的适配，不属于 Wails 的纯非激活浮窗逻辑。

Qt 适配还需在原生 panel 成为 key 后同步 `QWindow.requestActivate()`，否则 AppKit 已经把键盘交给浮窗，但 Qt 的 `isActive()`／输入上下文仍可能属于旧窗口。输入法宿主判断使用实际前台 PID；显式主窗口入口总是发送应用激活，覆盖关闭保护期间可能尚未完成的外部应用激活，不使用非激活 panel 下不可靠的 `isActive()` 作为省略条件。

成功完成依据 `taskOutcome == completed`，在展开和收起形态均显示绿色圆圈对号及“任务已完成”。任务失败、取消、启动失败不显示成功图标，下一条任务启动时清除完成状态。状态来源于 Codex 的任务结果，电脑控制释放结束后才发布。

`tests/test_agent_companion.py` 验证关闭、重新唤起、草稿保留和各任务状态；`tests/test_agent_computer_control.py` 验证真实任务结果与下一轮清除；`PROXIMIC_TEST_AGENT_NATIVE=1` 下的 `tests/test_agent_companion_native.py` 使用临时窗口验证关闭/重新唤起不会抬高、还原或显示主窗口。

## 同组多任务与轻量输入提示

所有任务卡片都提供“新建对话”（加号）：空闲、执行中、完成后均可建立空白卡片，首次发送时连接独立的 Codex 对话。各卡片保留自己的命令队列、授权请求、草稿、附件、输出和完成状态；新增会话使用独立运行目录，避免覆盖原任务的同步状态。叉号仅隐藏当前对话，运行中的任务仍由 Codex 继续执行；运行中且没有待发送内容时，输入区的发送按钮变为停止按钮，用来取消任务。

链接按钮打开右上角的小菜单，按最后更新时间倒序列出最近 5 条未归档本地对话，只显示标题，无搜索栏。菜单不改变浮窗尺寸，正文与输入区保持可见；Esc 或点击菜单外关闭，关闭点击不会提交草稿。右上角不再显示停止按钮，运行中可用输入区的停止按钮取消任务。选择后先连接目标，收到原生状态才替换当前卡片；失败保留原卡片和草稿。原来的草稿、附件和运行任务不会转移到目标会话。后续输入、截图、steer 和取消均绑定目标 thread/turn。正在听写、组字、选附件或截图时等待当前输入结束，防止一句话被交给另一条对话。

所有卡片共用浮窗管理器和原生焦点通道。只有鼠标或触摸板 click 选择其他任务，戒指的输入/发送/润色操作始终交给当前选中的会话；全局 Agent 唤起/返回手势仍返回同一张卡片。卡片编号可点击切换，屏幕放不下全部卡片时也能找到其他任务。卡片的非按钮、非文本输入区域可以拖动，整组按同一位移移动并约束在屏幕可用区域内，状态刷新保留拖动位置。浮窗不再显示“记录”按钮。

“没有可润色的文本”、输入未就绪和过期草稿等操作提示通过 `input_notice` 发送到输入法浮窗。该消息绑定连接 epoch 和前台 PID，有已激活的匹配输入客户端时显示在光标旁，否则显示在指针附近；不创建或修改输入事务，不激活应用，短暂显示后自动消失。这些提示不会写入任务错误字段或覆盖输出、标题、圆圈对号。真正的任务失败仍由任务结果展示。

`tests/test_agent_sessions.py` 覆盖独立发送/取消/授权、同名请求隔离、鼠标选择、整组拖动、按钮和输入区排除、完成状态保持和原生输入提示；输入法原生面板测试另行验证提示不获取焦点且下一次输入可以正常更新。
