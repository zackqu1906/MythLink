# 三句实验中的SDK点击与意外出字

原始会话：`data/stroke-test/20261013_171933_921318.jsonl`。本次仅分析，没有修改点击或提交策略。

## 代码链路

1. `src/ring_python_sdk/touchpad/core.py` 的 `ClickDetector` 从接触概率变化产生down/up。按200Hz帧号计时，接触长于0且小于40帧（200ms），移动帧完整，原始速度积分的净位移不超过0.02时输出click。没有用整条累计路径或最大活动范围排除移动接触。
2. 同一模块同时输出click和click_verdict；`src/proximic_ring/touchpad_strokes.py` 用结束帧号合并裁决，已解析帧号去重。点击裁决优先于笔画，即使接触收集到了有效轨迹，也清除轨迹并执行on_tap，而不输出笔画。
3. 测试程序 `accept_sdk_tap()` 立即调用 `commit(self.selected//5*5)`，确认当前页首候选。没有独立的书写状态、移动接触否决、提交后冷却或联想确认保护。没有笔序时也能提交下一字联想。

鼠标式点击容差与书写式笔画判定存在重叠。点击阈值用的是增益前的模型速度积分；轨迹展示使用不同的横纵比例与速度相关增益，不能将0.02直接当作显示位移阈值。原始小净位移仍可能形成明显显示轨迹。笔画收集器又接受长度至少1.5、至少5点的轨迹，因此同一接触可以同时满足“轨迹足够像笔画”和“SDK判为点击”，现有仲裁选择点击。

## 本次记录能确认什么

三轮内的36个SDK点击有36个不同结束帧号，未发现同一结束帧号重复出字。利用记录的接触边界和逐帧显示位移重建接触：

| 随后提交 | 接触时长 | 显示累计路径 | 正文目标 |
| --- | ---: | ---: | --- |
| 一 | 150ms | 5.54 | 穿 |
| 早 | 80ms | 2.36 | 时 |
| 亿 | 35ms | 4.88 | 向 |
| 是（第二轮第二次错误提交） | 175ms | 6.45 | 回 |
| 雹 | 120ms | 6.98 | 霓 |

上述移动多数接近直线，因此本批记录更突出的是移动容差与写字用途不匹配，不能只解释为来回移动导致净位移抵消。后者是代码规则存在的潜在风险，但未被这些代表样本直接证实。

36次点击中9次重建轨迹也满足现有笔画收集器的长度／点数门槛。这9次伴随7次错误提交、2次正确提交（方、不）。用户意图没有人工标签，正确文字可能也来自非预期接触，因此不能把正确提交等同于正确点击检测。

第二句“停→止”分别对应接触帧段43117–43132和43152–43172，是两个独立的SDK接触判定，不是同一事件重发。两段之间按帧号有100ms间隔；正文出字间隔约188ms。第二次在空笔序下提交联想“止”。既可能是手指短暂再次接触，也可能是接触概率分段抖动，当前日志无法分离这两种真实动作。

完整日志保留显示位移与接触诊断，但没有增益前的原始速度及明确的点击判定理由，也没有用户“正在写笔画／正在确认”的真值。因此不能完整重跑SDK点击阈值或证明每次错误提交都是误触。

## 可做的优化及收益边界

| 策略 | 这批记录上的静态筛选 | 代价与限制 |
| --- | --- | --- |
| 点击接触显示路径≥1.5时不允许直接确认 | 标记9次：7次错字、2次正确字 | 阈值只是借用已有笔画门槛，尚未校准；不能自动把被挡点击都追加为笔画 |
| 提交后250ms内抑制下一次点击确认 | 标记“止”这1次错误提交 | 针对此次连续提交有效；阈值要用真实用户复测，不能承诺对所有点击有效 |
| 空笔序时禁止点击选联想 | 标记9次：2次错字、7次正确字 | 损失正常联想，不适合作为默认长期方案；可作为诊断模式对照 |

这些只是对既有事件的静态筛选，不是修改后的端到端效率或误触率。改变早期提交后，后续笔序、候选和用户行为都会变化。

建议优先在书写应用层增加独立确认门控，保持共享SDK的鼠标行为：

1. 传递并记录接触start/end帧、时长、完整轨迹和原始净位移／累计位移，再决定是否接受SDK点击。明显移动的点击先不允许直接出字，保留已有笔序与该接触轨迹供复核；只有有充分证据像笔画时，才进入笔画识别。
2. 对完成提交后的短时间增加点击确认冷却，正常书写笔画和明确方向操作继续处理。用设备帧时间处理接触先后，不只用UI回调时间。
3. 将有笔序候选和空笔序联想分开管理。空笔序联想需要新的明确确认动作；过快的后续接触不能直接连发。保留方向选字等可预测的确认入口。
4. 不要以“写满标准笔画数”作为点击确认前提，避免破坏已经有效的前缀选字。也不要在实验中拿已知原文纠正识别或放行操作，否则不能代表实际使用。
5. 增加人工“误触”标记，以及click_allowed/click_suppressed和原因日志；采集正常轻触、短点笔、短横笔、写完换手和连续选联想的标注样本。对误确认率、被挡正常确认次数、重写次数和速度同时比较。

最小可验证版本应先做：点击轨迹诊断、明显移动的点击确认保护、提交后短冷却。随后再决定是否改SDK判定规则及具体阈值。仅加冷却无法解决“亿”等移动接触被当作点击的情况；仅缩小SDK时长也无法分开35ms的误提交与50–95ms的正常确认。
