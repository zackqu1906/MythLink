# macOS 应用手势

> 2026-10-15 更新：Chrome / Safari 网页媒体场景已改用浏览器扩展，浏览器 AX 播放器与文档识别路径已移除。下文较早的 AX 网页规则仅为历史记录。当前实现、安装与发布说明见 [浏览器扩展](BROWSER_EXTENSION.md)。原生应用场景规则不受此变化影响。


本功能根据前台应用选择一组原生快捷键。支持 Codex、WorkBuddy 和微信；不包含 Codex 项目选择器。仅更新源码，不需要更新输入法组件，也不构建 DMG。

当前配置入口统一为“手势控制”：未添加配置的应用使用全局配置，添加后应用映射优先，未绑定的手势仍回退到全局。安装扫描只提供候选应用，不自动添加方案。旧版 `appProfiles` 数据保留兼容，但不再作为运行时兜底。语音输入页展示六项输入手势及焦点覆盖提示。

Mythlink 自身也可在“添加应用”中选择并保存本地映射；源码运行和安装版使用同一配置标识。未添加、未绑定、删除绑定或清空配置时都沿用全局。普通主窗口和 Agent 任务窗口可执行这些动作，真实模态弹窗、权限请求和菜单仍保留拦截。浏览器的转圈默认绑定同样可在“默认配置”中移除；清空后不会在运行时补回，其他场景沿用应用常规绑定，再回退全局。

全局手势在后台线程复核前台目标，结果回到 Qt 线程后再次检查连接、配置版本、语音忙碌和事件时效。不能在 Qt 线程同步等待原生辅助功能复核：当前台正是 Mythlink 时，系统需要该线程回答窗口查询，同步等待会造成自身查询超时，握拳无法打开窗口选择器。复核失败会记录原生原因，便于区分捕获成功与执行前被取消。原生回归通过真实 Qt 窗口和窗口选择器验证这一路径，模拟测试还覆盖等待期间状态改变的取消行为。

## 戒指手势连接初始化

BLE 已连接只表示连接和服务可用，不等于设备已开始输出手势。每次新连接在服务就绪后保留至少 1 秒的稳定时间，再通过 `swipe_on(reset_device=True)` 发送一次手势 STOP、等待 250 ms 缓冲时间，然后发送 START。即使新建的 SDK 会话中 `swipe_active=False`，也执行这次设备端清理，避免依赖上一进程或连接退出后的固件状态。已有活动会话不重复初始化，也不因用户静止、没有手势事件而反复重启。取消连接会中止等待和未完成的启动。

当前手势协议没有启动回执。`[GESTURE_STARTUP]` 记录初始化命令；`[GESTURE_STATUS]` 中 `startup_evidence=start_sent` 仅代表命令已发出，收到有效设备包后才变为 `device_packets`，并记录设备包、触发包、无效包及回调错误数量。这些证据与应用分发后的 `received_events`、`processed_events` 分开。源码和 DMG 使用相同启动实现，安装包需要重新构建才会包含修复。

`tests/test_ring_gesture_startup.py` 用模拟设备验证旧状态清理、连接稳定时间、START 返回前的回包、首次连接及重连、启动失败和取消；不能替代实际戒指冷启动验收。

## 旧版快捷键配置兼容

| 手势 | Codex | WorkBuddy | 微信 |
| --- | --- | --- | --- |
| 上滑 | 发送：Return | 发送：Return | 发送：Return |
| 逆时针画圈 | 上一个任务/标签：Cmd+Shift+[ | 上一个任务：Cmd+[ | 上一个聊天：建议分配 Cmd+Shift+[ |
| 顺时针画圈 | 下一个任务/标签：Cmd+Shift+] | 下一个任务：Cmd+] | 下一个聊天：建议分配 Cmd+Shift+] |
| 食指捏合 | 新建任务：Cmd+N | 新建任务：Cmd+N | 不分配 |

双击 Tap 开始听写、单击 Tap 结束听写；两者可分别配置。左滑取消/撤销、右滑将仍有下划线的本句转为编辑，继续走语音逻辑。旧版本附带的“下滑撤销、上滑转编辑”别名自动移除；旧版默认单击 Tap 启停听写的配置迁移为双击开始、单击结束。新安装默认以手势开始/结束听写，已有的近场模式选择保留。

快捷键效果服从目标应用当前的原生行为。例如 Codex 上下切换可能切换任务或标签；发送键被用户在目标应用中改过时，需在 ProxiMic 同步调整。系统或应用的搜索框、菜单和可识别的弹窗不接收这些手势。

## 生效阶段

| 阶段 | 上滑发送 | 画圈切换 / 捏合新建 |
| --- | --- | --- |
| 空闲、定稿完成、编辑应用完成、撤销完成 | 立即发出一次发送快捷键 | 立即发出一次对应快捷键 |
| 正在开始听写、听写中、等待本句定稿 | 请求结束本句；真实 ASR 定稿并写入成功后发送一次 | 不执行、不排队；提示先结束听写 |
| 已转换为编辑、等待大模型、正在应用或撤销文本 | 不执行，给出短提示 | 不执行，给出短提示 |
| 取消、空句、定稿失败、等待超时、连接/目标/设置发生变化 | 取消先前等待的发送，需重新触发 | 不补发以前的手势 |

设备需要保持连接并开启手势识别；暂停语音识别或切换到其他输入法，不影响输入框失焦时的应用操作。发送时应将焦点放在消息输入框。听写中发送会固定到当时的应用、进程、窗口、输入控件和语音句子，最长等定稿 12 秒。短时间重复触发不会重复发送。

同一手势可以跨应用、全局和输入动作复用。只有与当前输入绑定冲突的手势受焦点优先级约束：输入框内执行输入动作，没有可撤销内容也不回退；失焦时使用应用／全局动作。其余手势不依赖输入焦点，按“当前场景 → 应用常规 → 全局默认”选择一个动作。修改输入主／备用绑定后立即更新冲突范围。开始语音和笔画输入沿用现有入口；语音操作进行中仍由本次输入接管，完成后再恢复应用／全局动作。

语音开始和显式切换输入法只检查当前前台应用的常规绑定及其启用场景中的绑定；其他应用、已停用场景或已移除配置不会要求当前输入框通过 AX 焦点判断。当前应用没有冲突且没有全局冲突时，开始手势也用实时 IMK 选区建立焦点证明，不查询 AX；结束手势保持原有路径。场景查询也限定于当前应用；查询期间前台应用或进程发生变化则取消本次路由。全局绑定继续参与冲突判断，当前应用的真实冲突仍按输入焦点与实际场景分配。

所有共用输入手势（包括左右滑、上下滑和开始语音）统一通过实时 IMK 回复确认输入焦点，不要求已经开始过语音。读取当前选区；尚未激活客户端则按固定前台 PID，通过系统已启用的“选择输入菜单中的下一个输入源”快捷键切入，并核对实际输入源及实时 IMK 回复，不切走前台应用来制造焦点。快捷键配置、事件投递权限不可用时停止并提示，不退回直接 TIS 切换或辅助窗口抢焦点。选区有效就使用输入入口；已绑定客户端明确返回无效选区 `[-1,-1]` 时交给应用／场景路由。AX 的文本分类和焦点缺失不再参与这层仲裁，浏览器扩展仍负责网页场景。回复缺失、选区字段缺失、激活失败或目标变化则停止，不把未知状态当成可输入或可执行快捷键。

应用路由独立保留原生前台进程、窗口、菜单、弹窗和页面身份校验；即使不做 AX 文本分类，明确存在的菜单或弹窗仍会拦截。共用手势执行前还会重新询问 IMK，确认连接、客户端、会话及输入状态没有变化；输入动作同时校验选区。输入源首次激活后，Qt 状态通知只有与本次 IMK 证明的身份完全相符，才能替换激活前的空闲身份，其他变化继续取消。手势提示浮层使用同一 IMK 判断。Safari 实测在 `AXFocusedUIElement=-25212` 的 PDF 页面仍能路由到切页快捷键；本机验证记录见 `.runtime/imk-gesture-audit/report.json`。

首次焦点探测的输入源选择和重试共用 800ms 预算，单次回复最多等待 200ms；已有 IMK 焦点不重复切换输入源。系统切换最多遍历一轮可用输入源，遇重复、无响应或前台变化停止；按键在 finally 中释放。启动时继续执行原有 BEGIN 握手及其超时校验，并在正式 BEGIN 回执上再次核对手势取得的连接、客户端、前台进程和光标位置。已有焦点证明时只 ping／BEGIN，不再执行旧辅助窗口恢复；上一句已结束且身份匹配的状态可以衔接下一句，其他旧事务不能接管。原生创建会话前不带选区的中间 idle 通知只继续等待，不能放行或误判焦点丢失。微信会在不同输入框之间复用客户端 ID，因此客户端仍存在或缓存的 `ready` 都不足以证明焦点。尚无语音会话的延迟输入动作也会重新读取实时状态。上滑 Enter 另固定原生窗口，并在发键前再次读取 IMK 确认。手势日志以 `input_method_focus` 标明 IMK 路径，`input_focus` 阶段记录探测耗时；输入框正文不进入这些诊断字段。

2026-10-21 复测修正：初版探测使用单独的 `select`，绕过了 2026-09-20 已有的 `ensure-selected` 焦点恢复，再次触发 activate 后立即 deactivate。历史依据见 [输入源停用诊断](INPUT_SOURCE_DEACTIVATION_DIAGNOSIS.md)。旧辅助窗口恢复仍保留给原有调用，但实测会关闭 Companion，未接入新的手势探测。新路径使用系统原生输入源快捷键；自建窗口和 Companion 原型已确认原文／光标或窗口保留，正式焦点＋空 BEGIN 流程已在两款应用各通过 3 次冷切入和 12 次连续启动。耗时和完整结果见本机 `.runtime/imk-start-validation/report.json`；这些测试没有录音或发送消息，不代表实物手势、ASR 或所有应用的验收。

同日实物 tap 崩溃补充：两份系统崩溃报告均停在后台线程 `TISCreateInputSourceList → dispatch_assert_queue`，属于输入源查询的线程错误。输入源列表、当前输入源、属性读取和 CF 对象释放现统一在 Cocoa 主队列执行；手势线程继续负责等待、轮询和切换按键。主队列等待计入原有总超时，过期排队查询不会迟到执行。`test_system_input_source_native.py` 在全新 Cocoa 进程中从后台调用真实 Ring tap 入口，模拟 IMK 回复但实际执行系统输入源读取，覆盖首次初始化和连续 50 次 tap；该测试不开麦、不切换输入源、不写入正文，不能代替实体戒指验收。

同日连续有文字输入补充：普通 ping 在上一句仍保留时返回该句的原始快照，光标与听写提交后的位置不同，不能用它确认新一句的焦点。固定目标的开始握手改用带 `start:` 请求标识的实时查询，等待期间忽略普通旧状态通知，并校验请求标识；收到新一句 BEGIN 回执后仍检查实时客户端与选区。已过期或重复的开始查询回复不能覆盖新会话。之前的空 BEGIN/reset 测试没有推进光标，未覆盖此问题；回归用例现在覆盖原位置 0、提交后位置 5 的连续启动，以及真实光标变化、无效选区和旧回复的拒绝。

发送或切换对话后，当前文本操作和撤销记录结束，不会继续把上一对话的撤销应用到新对话。完成态的主机记录会立即释放，忽略旧输入法回调，不影响下一句。

## 设置与微信配置

打开“手势控制”，在手部图示周围选择手势；点击、食拇捏合和中拇捏合可切换单次／双次。下方选择全局或应用范围，从分类菜单选择动作或录制自定快捷键，点击“保存更改”后生效。“还原”撤销当前手势未保存的选择；切换应用、场景或手势会分别保留本次页面中的草稿。应用栏的“配置管理”可进入场景切换、菜单刷新、恢复默认、清空与移除。设置中的“应用手势”入口也进入此页。这里配置的是 ProxiMic 发出的按键，不会改变目标应用自己的键位。

设置首页按“听写与撤销、手势与快捷键、麦克风与启停、语音识别、编辑模型、输入法与权限”分类。每页独立显示相关选项，返回按钮逐层返回；底部“完成”结束设置，修改自动保存。微信的详细填写说明位于“微信聊天切换 · 查看设置步骤”，不占用其他应用的设置页面。

微信没有采用已被用户验证无效的“Cmd+1 后上下键”方案。上一个/下一个聊天需要先配置 macOS App 快捷键：

1. 点击“打开 App 快捷键设置”。程序打开系统键盘设置，再定位到“键盘快捷键 → App 快捷键”，读取选中状态确认成功；不会修改任何系统选项。如果当前系统不允许定位，界面提供同一路径供手动进入。“功能键”开关与微信切换聊天无关，无需为此开启。
2. 设置页默认自动读取正在运行的微信版本和实际菜单语言，为“上一个聊天”“下一个聊天”分别列出系统对话框的三项填写内容：应用程序、菜单标题、键盘快捷键。菜单标题决定执行什么操作，必须原样填写，不能自行起名。只读取菜单，不读取聊天内容，也不根据 macOS 语言猜测。点击“＋”，应用选择微信 / Weixin，使用“复制菜单标题”粘贴准确标题。无法读取时可先展开微信的“显示 / Show”菜单再点“重新识别”，或手动选择简体、繁体、英文菜单名称。相同版本的微信也可能使用不同界面语言。
3. 点击系统的“键盘快捷键”输入框，按下填写说明中的组合键并保存。说明跟随用户当前设置的键位更新，不固定为默认键位。
4. 两项保存后即可回到微信使用画圈切换；没有测试按钮，也不需要勾选确认。旧版本未确认的状态不再阻止手势发出。更改微信切换键或菜单语言后，需同步更新系统配置；微信发送无需此配置。听写、编辑或撤销处理期间仍不切换聊天。

应用按键注入需要 macOS 辅助功能权限；源码运行时权限属于启动 Python 的应用/终端。应用快捷键不自动修改系统设置或处理授权弹窗。输入法切换是下述独立的显式手势动作。

## 验证范围

自动化覆盖阶段判断、识别时与执行时状态不一致、断连/窗口变化、发送去重、空句/错误、复用优先级、设置保存、微信无需测试确认即可发出当前配置的按键，以及使用模拟 macOS API 验证键码、修饰键、目标 PID 和成对按下/松开。QML 测试使用鼠标点击快捷键框后发送 Qt 键盘事件，验证默认录制、快捷键抢占、取消、非法字符、原生键码和退出录制；同时检查分类导航、小窗口布局和随语言及键位更新的微信填写说明。

自动化测试不会向真实 Codex、WorkBuddy 或微信发送消息。真实客户端快捷键效果还需在测试对话中验收；系统或客户端修改默认快捷键时可在设置调整。

## 手势切入语音输入法

单独切换输入法的功能保留，**默认关闭、未绑定手势**。用户在设置中绑定后，采用 macOS `TISSelectInputSource` 直接选中 Mythlink。此操作只切换，不开始听写；双击 tap 自动切换并开始听写是独立路径。启动和安装程序不会主动选中输入法。

- 设备已连接、固件手势通道就绪时生效；语音识别可以暂停，不限 Codex、微信等应用。
- 切换不受开始听写、听写中、等待定稿、编辑、写入或准备发送等缓存状态限制。输入法实际激活／失活由系统生命周期处理，不因旧状态提示“先完成本句”。
- 只切换输入法，不开启语音、不输入或发送文字；切换后按现有确认手势开始本句。已选中时不重复选择。
- 设置 → 手势与快捷键 → 切入 Mythlink：可以更换或关闭；只允许未被其他输入动作占用的手势；可与失焦时的应用／全局配置复用。已保存的有效绑定继续保留；未配置时不自动分配任何手势。
- 前台应用变化、过期识别事件、断连、快捷键录制期间不切换；组件未安装／未启用时显示具体提示，不自动安装或更改系统授权。
- 切回拼音仍使用系统输入法菜单或系统切换快捷键。
