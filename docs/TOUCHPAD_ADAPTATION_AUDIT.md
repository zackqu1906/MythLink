# Android → Mac 触摸板适配核查（2026-09-29）

结论：确认并修复 Mac 递归状态传输的覆盖错误。同一输入的异常可以由旧代码稳定复现，修正后无需静止校准便能消除已录制低波动区间的鼠标漂移。

## 证据与修复

用户提供 AAR 的 `jni/arm64-v8a/libring_touchpad_mnn.so` SHA-256：
`ff583bc39e57d811ff524a8b333ae1b0734c42c7ab3b574b7e7ff34c8fdc6528`。

用 macOS `objdump -d` 静态检查该 ELF，没有加载或执行 Android 二进制：

- `0x3ea8`：上传 token。
- `0x3efc–0x3f48`：上传全部 12 组独立 host 状态。
- `0x3f50`：执行 `runSession`。
- `0x3f94–0x3f9c`：将 velocities 输出复制到 host。
- `0x40a4–0x40ec`：将全部下一步状态复制到 host，循环内没有写 session 输入。
- `0x461c–0x4780`：reset 清零 12 组 host 状态。
- 构建 host Tensor 的 dimension 参数为 1（Caffe），与 Mac 一致。

旧 Mac 实现：每读取一个 `next_*` 输出便回写该状态的 session 输入。实际探针表明，只写 `conv_0` 就会改变 `next_ssm_0` 的数值；输入与输出复用同一内存区域。后续读取的是被破坏的状态，随后所有帧的推理受影响。

修复在 `run_probe.py` 的 `TouchpadBackbone`：在每次推理前上传完整的独立状态快照；推理后仅缓存完整的下一步状态；reset 清零 host 快照。未转换、重训或修改模型文件。

## 核对范围

| 项目 | 结果 |
| --- | --- |
| 模型 SHA-256 | 原 AAR 与 Mac 使用文件一致，见回放报告 |
| MNN 版本 | AAR libMNN 字符串为 3.6.1，Mac 安装版本为 3.6.1 |
| token 协议 | 与 Ring.java 中 `21 05` 解码一致：10 字节头，6 路 little-endian float16/帧 |
| 张量 | token `(1,1,6)`；6 个 conv `(1,256,4)`；6 个 ssm `(1,3,64,32)`；输出 `(1,5,3)` |
| 内存布局 | Caffe host 布局一致 |
| 状态顺序 | 修复后与 JNI 的 conv/ssm 交替顺序、全部缓存后下一步上传一致 |
| 后处理 | 核对 Java 中 200 帧预热、5 帧预测索引、sigmoid、速度增益表与轴缩放；本次未更改这些参数 |
| 校准与静止冻结 | 实时程序关闭 |
| 自动关闭 | 仍为启动后 90 秒，鼠标输出通道独立检查期限 |

## 离线验证

`state-transfer-audit.json` 记录原数据哈希及完整指标。共 27,790 个真实 token；无丢包重置。使用同一模型、同一数据、同一后处理比较旧传输方式和修复方式，全程未发送桌面事件。

第 60 秒起的低波动区间：

| 指标 | 旧版 | 修复后 |
| --- | ---: | ---: |
| 原始 vx 均值 | 0.779649 | -0.000793 |
| 原始 vy 均值 | -0.025186 | 0.000139 |
| 接触 logit 均值 | 7.51929 | -12.0035 |
| 后处理平均位移 | 2.892371 | 0 |
| 非零位移数 / 总输出数 | 14462 / 14462 | 0 / 14462 |

修复后原始速度仍存在微小非零值；鼠标位移为零来自原 AAR 自带的 0.1 单位死区，不是新增校准或冻结。

`test_backbone.py` 使用真实 MNN 对首帧所有状态快照进行检查：旧实现会在 `ssm_0` 出错（测试输入下 6144 个元素中 928 个不一致），修复后通过。另验证 240 帧之后重置、重放输出逐元素完全一致。全部 21 项离线测试通过。

此结论证明了具体适配错误及其修复效果。没有在 Android 手机上执行同一录制文件，因此尚未宣称跨平台逐帧数值一致；实际滑动方向、距离和点击体验仍需用户复测。
