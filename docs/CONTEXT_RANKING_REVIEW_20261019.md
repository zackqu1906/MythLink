# 上下文与完整模糊候选排序调整

## 最新记录的具体问题

记录：`20261019_165140_457918-trial-1792400081858158600.json`，目标「今天我用戒指输入一句话。」，实际结束在「今天我」。卡点主要发生在前文「今天我」之后输入「用」。

四次五笔组合均识别为 `szhhs`；「用」的字典编码为 `pzhhs`，仅第一笔不同。「用」已通过真实轨迹的模糊备选进入普通候选，原排名分别为 24、20、6、12。整字纠错合并后变为 26、22、8、14；即使普通候选已到第六位，也会被插入的两条纠错建议挤出首屏。普通字典完整匹配「叶／申／甲／叮」和大量更长字的严格前缀排在前面。

离线模型只保留每个上下文的八个后继字，没有「今天我→用」，也没有「我→用」。因此本次没有足够的直接词语上下文证据；不能把现有语言分数简单乘大就称为理解了「今天我用」。

## 最终实现

策略版本 3：

- 普通模糊排序的语言系数仍为 1，整字纠错仍为 0.35。无上下文、手动输入或没有合格完整备选时，沿用原候选顺序。
- 输入至少五笔，有已知前文上下文，且存在**笔画数已完整、仅一笔不同**的物理匹配候选时，考虑保留一个候选到第二位。
- 候选必须已经通过原有字典／轨迹匹配，模糊代价不超过 2.5，原语言加分至少 0.5。以语言权重 1.6 比较这些完整备选，保留一个最优项。没有加入新字，也没有突破模糊匹配或字表过滤门槛。
- 保留当前第一候选。若提到第二位的字原来不在前四个普通候选中，合并整字纠错时仅预留一个额外纠错位：原前四个普通候选、被提升的完整备选和第一条整字纠错均能留在首屏。所有其余候选仍可翻页。
- 相关候选带 `context_promoted` / `context_extra_slot` 元数据；测试日志与报告保存 `context_ranking` 策略快照。选择中的冻结规则继续沿用原实现。

没有添加对「用」或「今天我」的运行时特殊处理。测试原文只在候选生成后参与离线排名检查；实际排序只接受前文、笔画证据、字典与已有语言模型。

## 复核结果与限制

四次五笔「用」在普通候选和纠错合并后均为第二位；「叶」仍为第一位，需要用户选择正确候选。本次其他多笔／多处错误不保证恢复，单纯排序不能挽回已被匹配规则排除的字。

曾试算全局将普通语言系数增至 1.6、纠错系数增至 0.7；历史回放首屏新增 20 次、丢失 23 次，未采用该方案。最终只对上述完整模糊备选加强语言比较。

最终对 30 轮有可对齐前文的真实记录进行成对回放：2321 个可评分逐笔候选时刻，原首屏命中 994 次，新策略 999 次；新增 5 次、丢失 0 次。其中最新一轮可评分 49 次，首屏命中 11→15，新增的四次均为上述五笔「用」。这些是同一批历史记录的诊断结果，不能作为独立用户准确率或输入速度改善的证明。

回放固定使用当时记录的识别类别、距离和运动指标（包含当时个人学习的影响），只比较候选排序；没有重新识别轨迹，也没有在排序前提供目标字。异步整字纠错使用同步计算结果比较，因此回放排名不冒充当时屏幕截图。参考前文错位的时刻不评分。
