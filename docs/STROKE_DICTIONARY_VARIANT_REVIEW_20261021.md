# 笔画字典变体、纠错覆盖与候选排序检查

本文保留修改前的审计与仿真结果。用户随后选择保留整字／部件换序，移出其他变体；已实施的运行规则与数量见 [当前笔序过滤说明](STROKE_DICTIONARY_ORDERS.md)。

## 结论

「舌」类一笔差异适合从普通精确匹配移到带代价、带逐笔标注的纠错路径。当前默认6500字范围内，2043条变体只需一次笔画类别替换，涉及1887个字。「舌、乱、甜、适、敌」的首笔横／撇差异都属于此类，完整输入时在本次无上下文回放中均能通过现有整字纠错召回，得到“输入第1笔一→丿”的说明。

但“所有不同版本都能直接删除，由现有整字纠错等价接管”不成立。整字纠错至少3笔启动，3～5笔最多1次编辑、6笔起最多2次编辑，只搜索完整字，并截断到18个纠错候选。未写完的目标字可能暂时消失，较远变体和部分短字不能恢复。

本次只新增审计脚本和报告，没有修改运行字典、识别逻辑、字形资产或候选排序。

## 数据与口径

运行资产为 `src/proximic_ring/assets/strokes.json.gz`，共186955条字符—编码记录、102597个字符；默认6500字范围内有14147条记录。

比较参照是当前 `stroke-glyphs.json.gz` 中附在Hanzi Writer轮廓上的cnchar-order五类笔序标签。这是系统目前的显示参照，未经逐笔人工核验，不能仅凭不一致认定原字典错误，更不能将其称为已验证的国家标准笔顺。

按字符逐条比较字典编码，使用现有 `align_strokes` 的最优字符串对齐距离：类别替换、漏笔、多笔、相邻两笔交换各计一次编辑。另区分已验证的忄三笔映射与当前无法映射的变体。

6500字中129字缺轮廓、36字有轮廓但缺可用笔序标签；这165字的380条记录没有纳入不同笔序统计。另有“撅、炽、膝、黏”4字的显示参照编码并不存在于识别字典，共8条记录；需要先核对数据来源，不能删除到该字没有编码。

## 当前整字纠错能覆盖多少

不考虑排名，仅按当前启动条件、完整目标字编辑距离和编辑上限，7188条中5797条可到达当前显示参照，1385条超编辑预算、6条输入不足3笔。

6条短输入来自“丁hz、乃pz、九zp、了zz、匕hz、匕zp”。例如删除“丁hz”后，2笔输入仍不足以启动整字纠错。复杂差异包括“儒pshnzshhhhhpszss”相对显示参照4次编辑，当前最多2次编辑无法接管。

上述5797条包括4个参照缺失字中的部分记录，只描述距离条件，不代表当前字典实际存在纠错目标，也不代表能进入最终18个结果。

## 删除变体后的离线回放

仿真规则：对6500字中显示参照已存在的字只保留一条参照编码；缺字形、缺标签或参照本来不在字典的字保留全部旧记录，不改变6500字覆盖。共移出7428条普通字典编码，其中7180条为无法映射变体、248条为已验证的忄变体。

每条移出的完整编码作为一次手动输入查询。使用现有严格匹配前30字、整字纠错前18字和六格合并规则；没有上下文、Qwen选字、轨迹歧义、连笔或个人学习。搜索临时提高结果数量以测量被截断字的纠错排名，最终展示仍按18字截断。结果是字典回放，不是硬件识别准确率或真实使用频率加权测量。

普通候选列是当前代码的无上下文严格匹配回放，不冒充截图当时包含真实轨迹与前文的排名。删变体也不意味着这些字永远不能排第一；当它是最合适的纠错结果、没有更好的普通匹配时，仍可合理排在第一，关键是有代价和纠错标注。

“舌”在第4笔时，输入到完整参照的编辑距离是3，超过短输入1次预算；第5笔时距离2，仍超过1次预算；第6笔写完后才降到1次。因此仅删除变体、沿用当前整字纠错，会失去中途预测。修复到当前字的前缀并补全尚未写的尾部，才能使这一类差异从早期就进入统一纠错路径。

## 为什么变体会被排到前面

`StrokeDictionary.candidates` 把字典中的每条编码都当作合法普通匹配：完整编码匹配先排，再看字符排名。没有“与显示参照不同”的编辑代价。实时模糊匹配也以匹配到的字典编码为预期；输入正好符合变体时不会产生替换位置，完整无纠错匹配获得高优先级。

`BatchWorker` 在整字纠错查询中传入 `excluded_characters=chars`，已进入普通列表的字不会再进入纠错列表。因此变体不仅不用承担代价，也不会被后续整字纠错改成带颜色的修复解释。候选合并还会保留普通列表第一候选。

修复应放在匹配和候选证据层，不能仅修改“笔顺版本不同”的文案，或只在最终绘图时把它冒充普通完成字。

## 建议

1. 先核对统一显示／识别笔序的来源，单独处理缺标签和参照缺失字；保留原始来源表作审计。
2. 将已明确的一笔替换等非参照编码移出零代价普通匹配，将换序、替换、漏笔、多笔统一为有编辑证据的修复解释；使状态着色使用同一目标笔序。
3. 在删去大量变体前，让纠错支持当前前缀与未写尾部补全，避免“舌”在第4、5笔消失；短字启动条件与复杂差异另外决策，不直接全局扩大编辑预算。
4. 排序保留标准完整匹配的优先级，以纠错代价和已有轨迹证据比较修复候选；不以“来自另一版本”取得普通匹配的零代价。

## 复现与产物

```powershell
.runtime/venv/Scripts/python.exe tools/analyze_stroke_dictionary_variants.py
```

输出 `data/diagnostics/dictionary-variants/audit.json` 与同名CSV。CSV逐条列出7436条非参照编码、来源、对齐编辑、字形映射状态、当前预算覆盖、仿真纠错排名及合并后排名。JSON另含覆盖统计、案例、六个“舌”前缀回放与字典／字形／字表／忄注释的SHA-256。
