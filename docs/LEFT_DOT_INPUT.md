# 左点兼容输入

左点兼容已接入主程序和独立完整输入测试程序的模糊候选查询。重新打开 `scripts/test-complete-stroke-input.cmd`，保留“模糊匹配”和“常用／通用字（6500）”开启即可试用。

## 输入行为

保留标准五类笔序，在已标注的左点位置接受自动识别的撇／竖。例如宝第二笔、控第五笔、快第一笔、心第一笔。记录中的识别类别和屏幕笔画符号仍保留实际输入；候选层记录 `left_dot_corrections`，并沿用问号显示兼容解释。

左点在第一笔时也能找回以点开头的字；输入过程中按前缀匹配，不需要等到完整笔序才补回候选。多个已标注左点可以同时兼容，默认档位50时每处工程代价上限为0.45，不占用通用识别补救预算。该分数不是识别概率。现在可以通过 [动态模糊程度滑块](FUZZY_STRENGTH.md)调整代价和通用模糊阈值。

手动按钮指定的笔画保持锁定，关闭模糊识别恢复严格码表查询。右点、捺及未标注位置不增加新的撇／竖兼容。原有轨迹近邻解释和短末段补救继续保留。

排序依次优先完整的原码匹配、只通过已标注左点兼容得到的完整字、其他前缀／模糊候选；每组内仍使用兼容代价、字频和语境。因此“心”写成 `pznn` 时，“匀”这一完整原码匹配仍排第一，“心”排第二，而较长的前缀字排在后面。

## 标注数据

内置资产 `src/proximic_ring/assets/stroke-left-dots.json` 已按6500字范围重建，覆盖823个字、1841条现有笔顺变体，共1915个变体内位置，其中1369个位置带有构件映射来源。这些位置数包含同一字不同笔顺中的重复位置，不等同于1915种独立左点。

生成使用固定的 `cnchar-order@3.2.6` 笔形序列和 Make Me a Hanzi 的逐笔中线、构件分解及笔画映射。宀、忄、心、冖作为明确的构件模板，支持嵌套传播，例如控→空→穴→宀。逐笔标注还要求完整五类序列已存在于现有码表，并核对字形朝左下；方向例外和不能对齐的字列入复核记录。

竖心旁的点点竖、点竖点、竖点点单独处理左点位置。其他变体通过有界序列对齐传播，只有所有最优对齐都指向同一个点类位置才启用；632处变体位置因对齐不明确被跳过。字形笔数一致不单独构成启用依据。火部方向例外、膝的码表冲突暂未新增标注。

构件模板通过实际逐笔映射传播，不只依赖主部首字段。生成器还保存逐位置来源、原始文件SHA-256、版本与异常清单，便于后续人工复核。对应来源许可证及说明随安装包保留。

离线重建使用本轮已缓存的公开数据及许可证文件：

```powershell
.runtime\venv\Scripts\python.exe tools/build_left_dot_annotations.py
```

输入缓存为 `tmp/left-dot-research`；异常清单默认输出到 `data/diagnostics/left-dot-review/build-exceptions.json`。生成器不访问网络，不执行下载的JavaScript。运行时只读打包的标注资产。

## 验证

离线完整输入对照共10组，覆盖宝、实、控、窗、快的三种竖心旁笔顺、心、学和有两个左点的惋；模拟自动识别类别，不使用真实戒指。10组目标字全部进入前5候选，其中9组第一、心第二。记录保存在 `data/diagnostics/left-dot-review/candidate-validation.json`。这是规则和排名验证，不代表真实手写输入准确率。

旧3500字版本相关回归共220个不同测试通过（核心／本地界面与外部会话分批核验），覆盖首笔检索、前缀缓存隔离、多个左点与通用补救预算、手动锁定、严格模式、范围过滤、嵌套构件、模糊开关、退笔、提交及SDK模拟输入。原本地wheel包含标注、运行时模块及四份来源许可证／说明；扩展范围需从当前源码重新打包。

测试环境使用离屏Qt和Basic控件样式；模拟SDK后台线程需要允许相应系统调用。外部编辑器会话测试使用模拟macOS输入法，补全了在Windows测试主机上的平台夹具，未改变运行时的平台限制。下一步用真实戒指试写宝、窗、快、情、心、惋等，比较候选排名、重写次数与用时。
