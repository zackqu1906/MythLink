# 撤销、下一步与重做

多次撤销始终开启，旧开关已移除，忽略旧版关闭值。历史仅包含 Mythlink 的听写、编辑与润色，不接管手动打字、粘贴或其他应用的撤销栈。

## 三种互斥模式

设置 → 输入与控制 → “历史操作模式”（仅行内输入法显示）：

| 模式 | 左滑 | 定稿后右滑 |
| --- | --- | --- |
| 只撤销 | 上一步 | 不操作 |
| 撤销和下一步 | 上一步 | 恢复已保存结果，不请求模型 |
| 撤销和重做（默认） | 上一步 | 仅当撤销恢复出编辑指令时，用原输入再次请求模型 |

新设置保存为 `input/historyActionMode`：`undo` / `next` / `retry`。已有三选一选择优先；旧 `input/redoEnabled=true` 迁移为 `retry`，明确关闭迁移为 `undo`，无旧值默认 `retry`。迁移后移除旧键。

切换模式保留当前文字和撤销历史。离开“下一步”就清空缓存的未来步骤，切回不会复活旧分支。当前已恢复出的编辑指令在切到“重做”后立即可用。已经执行中的请求继续完成，切换只影响后续手势。

## 编辑指令与历史顺序

听写 A → 口述编辑指令 B 并应用 → 听写 C。连续左滑依次：移除 C → 撤销 B 的编辑结果、恢复原文和指令 B → 移除指令 B → 移除 A。

“下一步”按相反顺序恢复每一步文字和光标。“重做”只在恢复出 B 后可用，重新请求模型生成新的结果；删除 B 后不可重做。较早历史中的编辑指令同样适用，普通听写及润色还原不会变成编辑指令。

重做使用成功编辑时保存的原文、完整指令、实际传入的上文、编辑方式和模型设置，不重新录音、截图或读取后来一轮的上文。自动编辑复用当时确定的任务计划；手动＋编辑路由仍执行原有的一次分类与生成请求。模型失败或取消时保留已恢复的指令，可再次重做；新结果成功落字才形成新分支。迟到结果不能写入，等待模型或写入确认期间不排队右滑。

历史记录在原录音条目下追加每次编辑请求。请求字段 `reexecuted` 标记是否重新执行；详情逐次显示“是否重新执行：是 / 否”，含重新执行的条目显示“重新执行”标签。较早指令的再次执行仍归属原录音，不归到最新录音。

未定稿时右滑沿用原来的编辑行为。无可用下一步／重做指令时不操作，不调用系统撤销或重做；非文本场景保留原有应用／全局绑定。新录音完全取消不会抹掉“下一步”的旧分支。

## 生命周期和写入验证

历史限于连续拥有同一输入框期间。自动切回原输入法时保留快照，下次操作重新核对输入框、文字和光标；全部撤回后，“下一步”仍可恢复。手动改字、移动光标、换输入框、发送或断开连接后不继续操作旧历史。

原生 `CompositionUndoHistory` 保存过去、当前和缓存的未来步骤；`CompositionSession` 单独保存恢复出的编辑指令来源。收到 `retry_edit` 后先验证原文、指令、光标及无其他组合输入，再发送 `edit_requested`。模型返回后沿用单次写入和回读确认，不因失败重复写入。

IPC 保留 `redo` / `can_redo` 表示缓存下一步；增加 `history_action_mode`、`retry_edit`、`edit_retry_version: 1`、`can_retry_edit`、`retry_source_utterance_id`。主程序同时要求原生能力和对应请求快照，旧组件不会收到不支持的重做命令。主程序与输入法组件需一起更新。

## 既有性能基线

以下是旧版（历史上限 100 条）的性能基线。实验使用生产 `CompositionSession`／`CompositionUndoHistory` 和内存模拟客户端，连续听写 120 句，再测连续编辑。以下是 10 万字原文的单次调用中位耗时，单位毫秒：

| 阶段 | 关闭 | 开启 | 差值 |
| --- | ---: | ---: | ---: |
| 起句 | 0.0121 | 0.0136 | +0.0015 |
| 流式更新 | 0.0419 | 0.0412 | -0.0007 |
| 定稿 | 11.8570 | 11.8337 | -0.0233 |
| 编辑结果应用 | 60.7510 | 61.3870 | +0.6360 |

细小正负差异不能当作稳定收益或退化。这次实验没有发现栈开启后起句、partial、定稿的明显额外耗时；较长编辑记录的保存增加少量处理。120 句的客户端读取次数开关两组均为 960 次。原本对长文本做快照／核验的成本仍然存在，不能据此声称任意长度输入框都没有延迟。

历史额外保留的文本量：连续听写样本为 828 个 UTF-16 单元；10 次 10 万字编辑后为 2,000,181 个单元，约 3.8 MiB 的 UTF-16 文本。内存是主要新增成本。执行实际撤销时的耗时仍取决于要删除的句长、恢复的原文范围和目标应用响应，不能由内存模拟成绩推断。

上述数字不包含戒指、网络 ASR、模型、真实应用跨进程读写和屏幕绘制时间，不是端到端 tap 延迟。上一句收尾期间下一次 tap 的启动门控没有在本次修改。原始数据见 [performance.json](../experiments/ime_undo_history_20260918/performance.json)。可执行 `.build/input-method/undo-history-tests --benchmark` 复测。

### 历史状态往返核验（2026-11-10）

核验发现并修复：编辑成功后连续撤销至指令被删除，再用“下一步”只恢复指令时，旧记录层因 `final_applied` 已清空而误标“已取消”。现在保存 `mode.edit_ever_applied` 作为成功写入证据；旧记录在后续操作时仅从实际应用回执补足证据，不把模型完成当作写入成功。未成功应用就取消的编辑仍保持取消语义。

| 当前步骤 | 历史状态／结果 |
| --- | --- |
| 撤销某句听写 | 该句已撤回，不改变其他录音的状态 |
| 撤销编辑结果、恢复指令 | 编辑已撤回 |
| 再删除指令、再下一步恢复指令 | 编辑仍已撤回 |
| 下一步恢复编辑结果 | 清除撤回标签，详情已写入，显示恢复的结果 |
| 润色还原原句／下一步恢复润色 | 显示当前实际写入的原句／润色句 |
| 重做生成但尚未写入确认 | 不显示为已应用 |
| 重做成功／失败 | 新结果已写入／未完成，保留是否重新执行标记 |
