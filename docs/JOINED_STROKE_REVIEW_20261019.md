# 两轮连笔数据检查与完整测试接入

## 可用记录

使用session `a04e9c90-90c4-4307-b75d-bdd9bf795d8e` 的v2训练记录。原记录和导出的`joined-strokes-P01-train-70.json`是同一session、相同样本，建模只计算一次。

两轮共70条已确认轨迹：反6条、的6条、了6条、子6条、衤撇点6条，以及40条单笔对照。70条均有完整接触与原始位移，积分误差为0，无静止空轨迹。原记录另有24条重采记录及24次采集中断；它们保留在原文件中，不进入训练。

“了”和“子”的前两笔共享`zs/zz`输出，合并为一个形状家族；另外三个家族是反`pp/hp`、白／的`ps`、衤`pn`。模型只提出备选，不能把30条正确标签理解成可直接强制拆笔的证据。

## 检查结果和限制

每次完整留出一轮，用另一轮的35条建模板，双向检查：

|项目|结果|
|---|---:|
|连笔样本中，正确形状家族进入备选|30/30|
|理想其余笔画下，原模型目标字前五命中|6/30|
|同样回放下，加入连笔后目标字前五命中|30/30|
|单笔对照中，也会出现连笔备选|13/40|

这里的“整字回放”使用留出样本中的真实连笔轨迹，其余笔画以正确的手动编码补齐；反、的、了、子分别回放自身，衤回放补。没有使用语言上下文。形状选项没有读取本条提示标签。

这只是同一参与者、同一session内的逐轮检查；阈值是在这份数据上开发的启发式参数，不是未参与开发的新一轮独立验证，不代表连续整句实写准确率。尤其13条正常单笔也会激活备选，说明撇点／横撇弯钩等形状确有重叠，不能使用赢家通吃的分类器。

另用最终70条模型在实际完整Qt窗口回放30条轨迹，走真实手势判断、笔画接收、候选更新、字形显示和提交路径，目标字均在前五，均能确认入字；正常女的单笔撇点仍以一笔显示。其余笔画仍为手动正确编码，这个检查用于验证整合，不作为独立识别率。该机这次回放中，从接收连笔到同步候选计算结束，中位约26ms、最高约145ms，包含冷启动字形加载；不含蓝牙、等待抬手或Qwen延迟。

详细结果保存在本机：

- `data/diagnostics/joined-strokes/model-review.json`：逐轮检查、每条家族距离、前五候选和模型来源。
- `data/diagnostics/joined-strokes/ui-replay.json`：完整窗口回放。
- `data/models/joined-strokes/model.json.gz`：约83KB的本地模型。保存归一化特征和部件位置注释，不将原始采集记录加入内置模板资产。

## 完整测试中的行为

关闭旧测试窗口后，重新运行`scripts/test-complete-stroke-input.cmd`。侧栏默认勾选“连笔适配（本地样本）”，可取消勾选比较原行为，也可以用`--no-joined`启动原模式。

- 每条接触始终保存为一条物理证据。两笔解释只存在于候选路径中，原始笔序不被直接改写。
- 保持原首候选，在其后最多为两个不同连笔家族保留位置；按字符去重，显示数量沿用原设置。同一个字也可同时保留原单笔解释供记录比较。
- 每字最多使用一次连笔展开；候选位置必须由离线部件注释验证。当前有261个字符具备相关注释，包含反、的、了、子、好、字、学、被、初、补等；不把任意折笔或任意`pn`位置当作连笔。
- 分支先限制到有对应部件位置的字，再运行原模糊匹配，不为每个分支重扫全字库。除采集模板外，不新增运行时网络请求。
- 候选图显示“连笔1→2”，并按逻辑笔数显示已写进度。组成笔序仍显示真实落笔次数，可在侧栏看到两种计数。
- 退笔撤回一次完整接触，包括该接触的两个逻辑笔画；清空、出字和切换输入时一起清除。
- 选中连笔候选后，不将整条连笔轨迹送入旧的单笔个人学习，避免标签污染。
- 连笔可能造成物理接触数和逻辑笔数不同。有连笔歧义的本字剩余接触记录为`joined_contact_unscored`，不参与原来的单笔准确率；出字、速度、文本准确率和连笔提交事件仍记录。
- “候选一次显示”模式使用相同连笔分支；模型缺失或损坏时保留原识别并禁用连笔开关。

这次接入只作用于完整测试程序；主程序没有启用自动连笔解释。

## 复现

```powershell
.runtime\venv\Scripts\python.exe tools\build_joined_stroke_model.py
```

默认读取`data/recordings/joined-strokes`下的训练JSON，核对相同session的副本，拒绝冲突副本、不完整采集及无效轨迹。独立验证记录不加入训练。位置注释来自已缓存的部件与细笔顺资料，代码不下载数据。

回归覆盖单／双笔共存、普通撇点保护、部件位置限制、手动锁定、模糊滑块重算、真实落笔整组撤回、字形进度、提交与个人学习隔离、批量候选模式和模拟SDK链路。Windows模拟SDK测试需能建立本机回环socket；QML检查使用`QT_QUICK_CONTROLS_STYLE=Basic`，避免本机原生样式不支持自定义控件的警告。
