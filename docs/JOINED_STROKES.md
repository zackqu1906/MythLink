# 连笔适配方案与采集

2026-10-30更新：已按部件统一厂形／斤、白、了／子、衤与走之末段连笔，支持同字多处连笔。走之第一点单独写，只连第二、三笔。新建采集v3只补走之末两笔，默认26条，旧记录仍可续采。详见[部件连笔规则与实现](JOINED_COMPONENT_RULES.md)；下文v2说明保留为原采集方案记录。

## 当前结论

当前`TouchpadStrokeOutput`在一次完整接触结束后交付一条轨迹，`StrokeDictionary.recognize`只返回一个五类笔画；模糊匹配也基本按一条证据消耗一个编码。因此，仅给DTW增加模板，不能把一次接触恢复成两笔。

当前v2范围：反的前两笔、的的前两笔、了的整字、子的前两笔，以及衣字旁衤最后的撇和点。当前字典允许反`ppzn/hpzn`，的`pszhhpzn/pszhhpzh`，了`zs/zz`，子`zsh/zzh`，衤常用编码`nzspn`。采集同时保留这些合法变体，不能把某一种字典变体当成唯一真值。原始任务是弱标签：保存人确认已完成的字例及逻辑笔数，不伪造精确分割点。

建议实现“一条接触轨迹→一个或两个逻辑笔画的备选解释”，保留原来的单笔解释。尤其一笔了可能很像横撇弯钩，短撇接竖也可能很像普通折笔；几何信息不足时，后续笔画及候选字前缀参与消歧，不能强制所有弯折都拆笔。

## 分阶段实现

1. 用本工具补采连笔和正常单笔对照，确认接触边界没有被SDK错误切断，以及几何形状是否足以区分。保留原始尺度、每点时间、位移事件、接触边界和SDK点击判定。
2. 第一版离线模型比较完整轨迹的单笔模板和连笔模板。连笔模板直接输出`pp/hp/ps/zs/zz/pn`序列，不要求把连接线也识别成笔画。若需要分段，再搜索“第一笔结束—连接段—第二笔开始”两个边界，允许短连接段不计入逻辑笔画。只找一个曲率峰值容易把正常折笔切开。
3. 给每次物理接触保留带代价的可变长度解释，由候选字前缀匹配消耗1或2个编码。限制每字可用的连笔数量和额外代价；先只支持已采的几类。不要把两个独立证据无条件塞入现有模糊逻辑，否则会丢失单笔备选及分组信息。
4. 主程序整合时，为同一次物理接触保存分组ID；退一笔、人工改笔、清空、会话切换和候选解释都按该分组处理。删除、选字、点击仲裁仍要先通过完整接触检查，单独回归连笔被误判为手势的情况。
5. 用整次采集session划分开发与独立验证，避免同一遍书写被分到两边。比较：连笔恢复率、正常单笔误拆率、完整字前五候选命中率、抬手到候选更新耗时。等离线结果可接受，再在连续整字/句子中验证；孤立片段准确不等于输入已改善。

两轮70条数据现已用于本机实验模型，并接入完整测试程序，默认开启可关闭；原单笔解释仍保留，主程序尚未启用连笔。数据质量、逐轮检查和整合行为见[两轮数据检查与完整测试接入](JOINED_STROKE_REVIEW_20261019.md)。下面的分阶段方案保留为实现背景。

## 衣字旁的小撇点复用

用户已确认衣字旁衤（如被、补、初）最后的撇和点容易连写。现有撇点模板可以复用来判断几何形状；保留单笔`z`解释，另给连笔`pn`解释，再结合候选字中衤的对应位置及前后笔画消歧。正常“女”的第一笔撇点仍应作为一笔。不能把所有撇点直接改成两笔，也不能仅因候选编码恰好包含`pn`就放行。

当前DTW归一化路径大小，现有个人模板中也有只存归一化轨迹的记录；其分数不能单独证明这是一条“小”撇点，更没有衤两笔的真值标签。因此仍补采少量衣字旁连写、组成笔画单独写，以及小幅正常撇点对照。保存的`singleStrokeBaseline.shape_scores`已包含撇点模板距离，可用于离线检查能否直接复用模板。先不新增一个未经验证的拆笔阈值。

当前词库的候选增量已做离线检查：统一双解释主要增加早期候选，完整常用字未见新增完全匹配重码，但需要拆笔代价防止短字抢位。数据、限制与建议见[撇点词库检查](PIE_DIAN_DICTIONARY_REVIEW_20261019.md)。

## 如何采集

双击`scripts/collect-joined-strokes.cmd`。先断开主程序对戒指的连接，填写参与者和佩戴／实际写法，点击“建立新记录”，再连接戒指。

- 新建v2记录默认训练2轮，每轮35条，共70条：15条连笔（5个目标×自然／小幅／自然快写）、10条组成笔画单独书写、10条易混淆正常笔画。已有v1记录保持每轮24条的原计划、原标签和草稿续采；需要新增任务时建立新记录。
- 正常对照包含横撇、横折、横折钩、横撇弯钩、撇折、撇点、竖折、竖钩、弯钩，并加采小幅正常撇点；这些对照用于检查误拆。衤只采末尾的撇点连写，子只采前两笔，不写子的最后一横。
- 按1开始一条，完成后抬手；按1保存并准备下一条，按2重采。连笔任务中途不要抬手，单笔任务只写指定一笔，不写整个字。按错提示、漏写或意外抬手才重采，不按模型预测或屏幕好不好看筛样本。
- 本窗口采完整SDK接触，保留短接触和静止接触，不经过生产笔画／手势过滤。单笔DTW基线在保存时运行，结果只写JSON，不展示预测诱导改写法。基线模型文件哈希和参数随样本保存。
- 可把轮数改成1先试35条，支持“续采JSON”。每次抬手草稿、保存、重采均自动备份。此轮记录不能直接混进普通单笔模板训练。
- 训练完成后，另建“独立验证”2轮70条；稍后或重新佩戴后采。不要用验证记录反复调阈值。

数据存入`data/recordings/joined-strokes/joined-strokes-<sessionId>.json`，旁边的`.events.jsonl`保留全流事件。把该目录内JSON及对应事件文件一起提供即可。原有笔画采集记录多数只有单笔标签，无法代替这次两笔真值。

离线质量报告：

```powershell
.runtime\venv\Scripts\python.exe tools\analyze_joined_strokes.py
```

默认检查该目录下所有记录，拒绝重复sessionId和轨迹／原始位移不一致的数据。输出`data/diagnostics/joined-strokes/audit.json`，按训练／验证分开统计覆盖、时长、路径长度及旧模型具体笔形分布。它不是连笔恢复率报告。

## 用户确认后的范围

在此前列出的扩展候选中，用户仅确认“子”的前两笔需要适配，并另补充了衣字旁衤末尾的撇点连写。v2只加入这两组；亻、氵、讠、彳、两点、又、一般撇捺组合、心、冫均不纳入。子以“好、字、学”中的部件写法作提示；衤以“被、补、初”为提示，均只采指定两笔。

正常单笔撇点在两版中都保留为`z`；新增衤连写标为`pn`。两者不能合并成同一种训练标签。
