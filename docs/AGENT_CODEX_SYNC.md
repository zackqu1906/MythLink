# Agent 与 Codex 实时同步

## 使用

重新启动使用这份代码的 Mythlink 并连接 Agent。首次发送任务会在后台创建持久 Codex 对话；浮窗的“在 Codex 中打开”可显式打开同一对话。打开、收起浮窗不创建另一份执行任务。当前后台执行和生命周期以 `AGENT_CODEX_NATIVE.md` 开头的说明为准。

浮窗和 Codex 共享当前连接创建或通过链接按钮选择的 thread。后续消息、steer 和取消始终发送到选中的会话；授权和追问可在浮窗或 Codex 处理。链接按钮可连接最近的本地历史对话；加号建立空白会话，首次发送时创建新 thread。叉号仅隐藏浮窗，保留对话和未发送草稿。

截图逻辑保留以下三种模式，默认使用按需模式：

* **按需截图（默认）**：发送时立即在本机保存当前窗口的一帧，仅把路径、时间和窗口信息随消息传入。Agent 根据完整任务语义决定是否用图像工具读取这张图；不再用关键词或正则判断，也不等待模型判断后再截取桌面。
* **每次截图**：每次普通任务或修改任务时附带窗口图像。
* **自动截图关**：只发送文字和手动附件。

已有图片附件时不重复自动截图；回答 Agent 的追问不触发自动截图。原来的圈选截图、粘贴和文件附件仍可使用。

按需模式不会自动发送 `localImage`；纯文字任务可以不读取图片。每次截图模式仍直接发送 `localImage`。两种模式都保留截图时间和重新读取的窗口标题、应用信息，不沿用旧页面的文档 URL。提示词要求理解消息指代时使用这张保存的画面，不用后来桌面的截图替代；实际操作前仍核实目标的当前状态。截图内容都是观察数据，不能把窗口内文字当作新指令或据此猜测文件路径。

每次提交同步按 WindowServer 的前后顺序锁定当前可见普通窗口，再立即启动截图工作线程，排除 Agent 等输入浮窗；Agent 占焦点时截取其背后的当前窗口，不切换焦点或激活主窗口。页面、标签页、标题变化及旧唤起记录超过 120 秒都不阻止截图。选定后仍按窗口 ID 和 PID 精确截取，不自动退回全屏或另一个窗口。图片保存为仅当前用户可读写的独立文件，排队任务、后续输入和 steer 均携带自己提交时的路径。

语音上滑发送在等待识别定稿前就开始保存画面，定稿后沿用同一截图。语音取消、焦点/任务绑定失效时丢弃未提交的截图。系统获取画面共用从发送动作开始的一秒时限，超过时限则不使用返回的迟到画面；图片编码和模型读取不改变已冻结的内容。这个时限是异常保护，不能保证精确到点击同一毫秒；发送瞬间原窗口仍在快速变化时，画面取决于系统返回的那一帧。

目标在截取过程中关闭、缺少屏幕录制权限或截图失败时，仍发送原任务和手动附件，只通过输入法提示浮窗说明本次未附带自动截图，不覆盖任务结果。窗口观察或焦点记录刷新不阻止同一条消息发送；截图期间若文字、附件、会话或当前 turn 变化，整条提交作废，保留草稿并提示重新提交。

## 实现与兼容范围

以下为早期同步桥接的历史实现记录，当前后台执行协议见 `AGENT_CODEX_NATIVE.md`。

任务仍由 Mythlink 的单个 App Server 执行。`codex_ipc.py` 通过 Codex 的本机 Unix socket 建立独立客户端；`codex_bridge.py` 只声明本次连接创建的 thread 的所有权。Codex 是该任务的跟随窗口，输入转交给同一个执行方。

使用桌面端内部协调协议，而非公开稳定 API。适配的 macOS 桌面 build 为 **20156**（26.1007.30912）和 **20770**（26.1013.40934，CLI 0.163.0-alpha.10.2），两者状态广播版本均为 11。未验证版本明确显示实时同步不可用，保留现有持久化历史功能。更新 Codex 后需要验证协议、消息解析契约并更新版本门限；不能直接删除门限。

传输校验本机 socket 所有者和权限，限制帧尺寸与队列长度。网络线程只收发数据，所有任务操作在原 Flow 事件循环处理。请求按来源与 request ID 去重；发起和修改等回执在 App Server 应答后返回。状态最多每 100 ms 推送一次，仅发给订阅当前 thread 的客户端。

已连接的同步通道丢失时，停止并关闭原执行方，避免 Codex 恢复任务后形成两个执行者；重新连接创建新会话。没有写入或修改 Codex 数据库、历史日志或应用包。关闭 Mythlink 后历史仍保留，但不保证客户端专有动态工具可在原生窗口独立恢复。

本版没有接入 Codex 的更换工作目录/权限配置、编辑历史消息、压缩会话、队列管理、云环境恢复及应用模型上下文等高级请求。包含未支持上下文的输入明确报错，不把第三方内容转换成可信用户输入。模型发出的授权仍按原有逐次/自动授权设置处理。

## 验证

### “hit a snag” 修复

原先的协议验证漏掉了桌面渲染要求。2026-10-20 的实际桌面错误记录显示，跟随订阅成功后仍出现 `Cannot read properties of undefined (reading 'some')`。App Server 允许文本输入省略 `text_elements`，Codex 的续接消息检测却直接调用 `text_elements.some(...)`，因此在显示首轮参数时就可能崩溃。单纯升级 Codex 不能修复这项数据缺失。

`DesktopState` 现在在投影边界补齐文本数组，覆盖首轮参数、用户消息和修改任务消息；图片、有效占位信息及原始 RPC 消息保持原样。新增回归覆盖纯文字、自动截图说明、文件说明以及首个消息项到达前的状态。

本机升级后的独立 App Server 还遇到了模型连接超时和 TLS EOF。沿用系统已启用的 HTTP/HTTPS 代理后请求恢复正常。`network_env.py` 为 Mac 上没有显式代理环境配置的子进程读取系统静态代理，并保留本机地址和系统例外地址的直连规则；不修改系统设置，不覆盖调用方显式设置，不把仅有 PAC 的配置猜成静态代理。

`test_agent_codex_sync_native.py` 可读取已安装应用的协议版本表，在独立 Node VM 中运行其实际文本检测函数：先断言旧输入会复现相同崩溃，再验证修复后的首轮及用户消息输入。该测试不导入应用模块、不修改应用包，也不代表原生界面的完整视觉验收。

```sh
PROXIMIC_TEST_CODEX_CONTRACT=1 PYTHONPATH=src \
  .runtime/venv/bin/python -m pytest tests/test_agent_codex_sync_native.py
```

新版 build 20770 的实际验证：

* 打开隔离测试会话，原生 Codex 成为跟随窗口；测试期间的桌面日志没有新增 `error boundary`。
* 经本机协调协议发起后续任务、修改正在执行的任务，实际模型回复“双向修改成功”，修改前后 turn ID 相同。
* 同一通道回答 `ask_ring_user` 的选项 B，实际模型收到并回复 B；停止任务收到正确 turn ID 的完成回执。
* 清除开发聊天来源标识、不手动设置代理环境变量后，最终代码独立启动并完成文字任务。
* 在原生 Codex 打开的情况下发送合成蓝色图片及自动截图说明，模型正确回复“蓝色”，页面日志没有新增渲染错误。此项验证图片发送与显示链路，窗口捕获本身沿用下述独立测试。
* 最终相关回归为 221 项通过、1 项沙箱 socket 测试跳过；该项随后在本机单独通过，共 222 项通过。当前运行的源码版 Mythlink 已正常退出并重新启动以加载修复，临时测试会话已关闭并归档。

协议发消息使用测试客户端，而不是自动点击 Codex 输入框；不能据此声称完成了原生输入框的手动交互验收。集成记录位于 `.runtime/codex-20770-proxy-check/` 和 `.runtime/codex-20770-auto-check/`。

### 早期协议与截图验证

2026-10-20：

* 通过真实 App Server 与本机协调路由创建隔离会话，原生 Codex 打开后收到实际跟随订阅。
* 协议跟随端发起任务、执行中修改要求，最终回复“双向修改成功”，前后保持同一 turn ID。

* 单元/Qt 测试覆盖协议分帧、版本及会话隔离、重复请求、服务端拒绝、连接丢失、流式历史、截图触发、异步草稿绑定、图片输入和按钮操作。
